# 诺诺动作库规划（草案 v1 · 待院长裁决）

> 依据：R-058 需求池核心理念"诺诺是 LLM 大脑自主调用程序执行动作的独立个体"——动作=LLM 工具调用的执行端点。本文定义**做哪些动作、怎么触发、什么优先级**；技术管线可行性见[Mixamo到VRM动作管线调研](../00-调研/01-技术/Mixamo到VRM动作管线调研.md)。
> 状态：文档先行草案（2026-10-03 黑机），⚖️ 项院长裁决后生效。直播间集成按 10-01 裁决推后，本文只做前置规划。

## 一、设计原则（源自既有裁决，不需重新讨论）

1. **直播间机位=全景全身出境**（2026-10-04 院长裁决，修正本文件旧稿的头胸特写假定）：诺诺全身始终在画面内——动作清单以**全身可读**为标准，腿部/脚步/站姿位移与上半身同优先级；穿模治理不能依赖"镜头遮下半身"的兜底（PoC 里 y=1.35 的头胸相机只是开发调试机位，不是产品机位）
2. **动作来源=自研为主**（2026-10-04 院长裁决）：Mixamo 免费库数量/变体有限，"筛选动作"不构成穿模或选型的长期方案——自研动作工作流（AI 初稿→Blender 精修→.vrma 入库）是主路线，Mixamo 仅作管线验证的临时资产
2. **动作是 LLM 的工具**：不是动画师排播，而是 nonoAgent 根据对话语境自主调用（现有 `(动作:xxx)` 标记是预留语义，v2 升级为工具调用 schema）
3. **清冷底线**：默认脸绝不带笑——动作同规矩，热情系动作（大幅挥手/比心）要收敛，符合"外清冷内温柔傲娇"
4. **实时期优先**（设计红线）：动作 clip 播放不得显著增加回复延迟——预加载动作库，调用即播

## 二、MVP 动作清单（按优先级）

### P0（动作管线 Step 0 验收集，4 个）

| 动作 | 语义 | 触发场景 | Mixamo 候选方向 |
|---|---|---|---|
| wave | 问候/回应关注 | 观众进入、诺诺主动开口 | Waving（收敛幅度版） |
| nod | 认同/应答 | 听到弹幕表示理解 | Agree / Nod |
| headshake | 否定/拒绝 | 弹幕提过分要求时 | Disagree |
| think | 思考停顿 | 回复组织中的填充动作 | Thinking / Looking Around |

### P1（情绪表达集，4 个——与表情差分联动）

| 动作 | 语义 | 备注 |
|---|---|---|
| shy | 害羞/被调侃 | 双手微抬挡脸倾向 + happy/sad 表情叠加，傲娇核心动作 |
| surprised | 惊讶 | 突然弹幕/意外内容，配合 surprised 表情 |
| clap | 开心/庆祝 | 收获好感度事件 |
| doze | 打瞌睡 | 30 分钟无新内容的 idle 演出（需求池原始设定），配合 blink 频率降低 |

### P2（场景依赖集，动作管线后期）

- **read/write**：书桌看书/写字（依赖椅子+书桌场景道具，动作+挂点）
- **sit**：坐下基姿（场景阶段的基座，P2 动作的前置）
- **stretch**：伸懒腰（久坐起身过渡）

## 二点五、基层动作体系（基元草案 v1 · 院长 2026-10-04 确立方向"一套基层动作搭建整个行为大厦"）

> **⚠️ 2026-10-05 已被替代**：本节 L0~L3 行为分类草案经院长裁决演进出正式方案——**基元=平移/弯曲/旋转**（姿态是合成结果不是基元），架构详见 **[诺诺小脑架构设计（施工图）](诺诺小脑架构设计.md)**。本节原文保留作历史。

**分层设计**（上层=LLM 工具调用的执行端点，下层为上层供能）：

| 层 | 类型 | 基元 | 来源 |
|---|---|---|---|
| L0 | 姿态基元（保持型，时长任意） | 站直/放松站/坐/倚靠/蹲 | 程序化姿势+动作库 |
| L1 | 循环基元（循环型） | 呼吸✅/眨眼✅/踱步/左右张望/抖脚 | 呼吸眨眼已实现（PoC），其余程序化 |
| L2 | 语义基元（一次型，≤3s） | 点头/摇头/挥手/思考/害羞/惊讶/鼓掌/打瞌睡 | **AI 动作工厂**（见 §二点六）+ Quaternius CC0 库补充 |
| L3 | 移动基元（位移型） | 走/跑/转身/走近书桌/坐下起立 | 步态 clip+程序化位移 |
| 独立 | 表情通道 | happy/angry/sad/...（已有 expressionManager） | 与上述各层**任意叠加** |

**组合语法**：LLM 工具调用输出基元序列+参数（`{primitives:[...], params}`），运行时分层合成——姿态打底、循环垫层、语义/移动覆盖、表情独立。**基元设计四原则：短（≤3s）、局部（单部位群主导）、可打断、可叠加**——天然低穿模（大幅全身动作由基元序列拼装而非整段 clip）。
**与 clip 库的关系**：clip（.vrma）管复杂演出（L2 语义基元的实体、L3 步态），基元系统管日常微动作与运行时组合——两层并存，clip 是基元的素材来源之一。

## 三、触发语义（nonoAgent 工具调用 schema草案）

现状：nonoAgent 输出文本里 `(动作:xxx)` 标记（v1 预留，PoC 阶段）。
v2 目标（直播间集成阶段）：

```json
{ "action": "wave", "intensity": "subtle|normal", "duration_s": 2.0 }
```

- 动作库预加载，调用即播（不阻塞文本流）
- 动作可被打断：新弹幕到来时高优先级动作覆盖低优先级（doze 最易被打断）
- 表情与动作独立通道：动作管骨骼，表情管 morphTarget，可叠加（shy = 动作+表情组合调用）

## 四、与现有资产/阶段的衔接

- **骨骼设置（当前站）**：v5 模型是 VRoid 标准 Humanoid 骨骼，Mixamo 重定向无缺骨风险；Blender 骨骼设置阶段如需加辅助骨（发饰/裙摆物理），不影响 Mixamo 动画重定向主干
- **表情差分（Krita 轮后）**：P1 动作需要表情叠加通道，形状键体系已具备（Fcl_ALL_* 全套在）
- **场景道具（后期）**：P2 动作的挂点需求（椅子坐姿/书桌）在场景建模时预留骨骼挂点——BUG-084 入档的"挂骨对象静息基准存局部参考系"铁律直接适用
- **桌面端离线版**：动作库（.vrma）与模型分离，桌面端产品线直接复用同一套动作资产

## 六、家具交互（细节交互需求 · 院长 2026-10-08 提出，待白机实施）

> 院长原话："后续是需要更细节的交互，比如让诺诺去关灯，让诺诺移动椅子。**第一版允许程序示教，第二版就需要要求诺诺的大脑实现自主判断，选择如何移动椅子**。比如起身的时候，先将椅子向后推再起身。坐椅子的时候，可以选择坐下后，再拉着椅子移动到桌前。可以选择坐着椅子四处滑动。"
> 归属：**白机**（纯引擎/配方/大脑工作，不需要 Blender/Krita）。本文档记录需求与设计要点，实施细节由白机出方案后院长裁决。

### 6.1 场景清单（院长示例，非穷举）

| # | 场景 | 说明 | 已有基建 |
|---|---|---|---|
| F1 | **去关灯 / 开灯** | 走到墙边开关 → 抬手操作 → 灯态切换 | `roomApi.toggleLamp()` 已有（HUD/墙上按钮已在用）；缺"走到开关 + 伸手按"的示教动作与锚点 |
| F2 | **起身前把椅子向后推** | 坐姿起身的预备动作：手扶椅面/扶手，椅子后退 ~0.2m 再起身 | 椅子目前是**静态 collider**（`colliders` 里 5 个 AABB），需先"可动化" |
| F3 | **坐下后拉着椅子移动到桌前** | 落座 → 手扶椅面/桌沿 → 连人带椅滑到桌沿位 | 需要"人-椅刚性绑定移动"（角色的 root 随椅子位移） |
| F4 | **坐着椅子四处滑动** | 以椅为载具在房间内移动（办公椅的轮子感） | 同上 + 移动的**目标点/朝向**由大脑或示教给出 |
| F5 | （延伸）其他家具 | 如开合抽屉/推床/拿放桌面物件——同类问题的不同实例 | 结论：**家具交互建议统一抽象**，不做逐家具硬编码（BUG-097 教训同源） |

### 6.2 两阶段策略（院长裁决）

- **第一版 = 程序示教**：把 F1~F4 等场景写成**命名流程**（配方/时序脚本），由 HUD 或语义层直接调用（`push_chair_before_standup`、`slide_chair_to_desk`…），不做自主决策。目的：先把"家具可动 + 人椅联动 + 动作配合"的**引擎能力**打通。
- **第二版 = 大脑自主**：由 nonoAgent 判断"如何移动椅子"——是否推、先推还是先起、滑向哪里、滑多久，小脑只负责执行。要求第一版就留好**语义调用接口**（工具调用 schema 见 §三）+ **完成/失败事件回调**（大脑需要知道"移到位了没有"）。

### 6.3 设计要点（白机实施前需明确）

1. **家具可动化**：椅子从静态 collider 升级为"可移动实体"（位置/朝向 + 碰撞盒随动 + 路点图/寻路的动态更新——`segClear` 每段都会查 colliders，家具动后需重算或重铺路点）
2. **人-椅联动**：坐着滑动时角色的 root 与椅子构成刚体（同速同向），起身推椅时是"手-椅接触 + 椅子受推位移 + 人反向站稳"的力学近似；两者的**时序与插值**都要避免脚底打滑（与步态轮同源问题）
3. **交互锚点扩展**：现有 `chair.sit/chair.stand/bed.sit/room.center` 是**静态**锚点；家具动后锚点必须随家具坐标更新（当前 anchors 是 buildRoom 时的常量）
4. **与大脑的接口**：语义层需能表达"移动家具"这类**改变环境**的调用（不只是改变自身姿态）；建议 schema：`{ action:"move_furniture", target:"chair", to:{...}|"behind", style:"push|pull|ride" }`
5. **不做逐家具硬编码**（BUG-097 教训）：优先做**通用位移基元 + 家具挂点/接触点**体系（家具侧预留挂点，与 §四"场景道具"条一致）
6. **与动捕/剪辑的关系**：推椅/拉椅是"手部接触 + 全身发力"的动作，属 Phase B 配方库/动捕编译器的输入之一；第一版程序示教可用现有基元拼（旋转/弯曲/平移）+ 时序编排
