## 二、画质路线（五层）与引擎决策

### 2.1 画质差距五层（收益递减、成本递增）

| 层 | 做什么 | 工具 | 成本 | 收益 |
|---|---|---|---|---|
| ① 贴图层 | 泪痣/瞳色/发色渐变/眉粗细、轮廓宽度贴图、手绘固定阴影 | Krita + VRM 内嵌贴图替换（解包→原 UV 布局作画→回包，风险最低）或 VRoid 内贴图编辑（入口待 2.14 界面核实） | 1-2 天 | 大（决定「像不像定稿形象」） |
| ② 材质/渲染层 | MToon 参数、后处理（Bloom/浅景深/色彩分级）、灯光三件套与机位 | three.js | 3-5 天 | 中-大 |
| ③ 自研 shader 层 | 面部 SDF 阴影、手工法线控制明暗二分 | three.js 自写材质 | 1-2 周 | 大（动漫脸感决定层，MToon 缺失） |
| ④ 网格层 | 脸部结构/密度、眼球总成、发束、身体线条、删遮挡面 | Blender + VRM 插件 | 数周 | 中-大（半写实下收益上移） |
| ⑤ 绑定层 | 表情形状键/面骨/物理（§四 Step 5） | Blender | 数周 | 大（生动度） |

### 2.2 引擎取舍（W1~W4）

| 路线 | 画质上限 | 成本/风险 |
|---|---|---|
| W1 three.js 现状 + 资产精修（本方案主路线） | 高配 3D VTuber 级 | 低-中 |
| W2 + 自研 toon shader | 再上一档 | 中 |
| W3 迁 Unity（UTS2/lilToon/MagicaCloth 生态成熟） | 最高 | 高（工程量+与 Vue 站集成；但服务「桌面离线版」产品线） |
| W4 混合：实时走 Web + 特写/演出镜头离线预渲染 CG 图 | 「番剧级瞬间」 | 低，性价比最高 |

**决策**：二期按 W1 起步，W4 补特写镜头；W2/W3 留到审美验收明确不够时再评估。

### 2.3 半写实风格的技术影响

- **材质混合**：MToon 保留为整体统一基底；眼睛/皮肤/皮革等关键部位用 PBR（three.js MeshPhysicalMaterial 的 clearcoat/sheen/transmission）；同一条 VRM 内两种材质可并存
- **皮肤 SSS 缺失**：three.js 无次表面散射，透光感烘进贴图或自研——归 shader 层，不阻塞建模
- **光照统一**：半写实角色 + 写实场景需角色单独光照参数组（业内常规，集成期处理）
- **AI 分工**：AI 生成 3D 对角色无用（拓扑不可绑定/风格化无承诺，调研已核验），仅头饰/道具/硬表面有辅助价值；AI 生图可做贴图基材与参考。**瓶颈在人的造型/手绘能力，不在工具授权**

## 三、眼球总成（第一动手项）

**病根判断**：VRoid 的眼部是面部网格上的一片贴图区，不是真眼球——转动无视差，远看永远是贴图在动。半写实路线下这是最容易做出真实感、最易与普通虚拟主播拉开差距的部位。

**组件清单**（Blender 内建「眼球总成」）：

| 组件 | 说明 | 驱动手段（VRM1.0 → three-vrm 均通） |
|---|---|---|
| 巩膜球 | 真球体几何（非贴片） | eye bones + lookAt（球体后产生视差=「活」的最大来源） |
| 虹膜盘 | 纤维放射纹+瞳孔缘深色环+外缘暗环，贴图带深度（视差/法线） | — |
| 瞳孔层 | 独立可缩放（情绪/光反应） | 形状键，或 VRM1.0 `textureTransformBinds`（缩虹膜 UV 不动几何） |
| 角膜凸起 | 透明/清漆材质带镜面高光（湿润感来源） | — |
| 高光板 | catchlight 独立层，可动/调强/可关 | UV 动画（MToon 规格支持）或 `materialColorBinds`；失神/泪光/黑化全靠它 |
| 上下睫毛 | 独立 mesh + alpha | — |
| 下睑湿线 | 泪膜细节 | — |

**硬约束**：①眼球与眼睑必须同一批改（眼球换几何后眼睑不重新贴合必穿模），连脸型构成「脸部冻结」批次；②验收必须含**眼部特写（CU）镜头**——眼睛的活儿只有特写看得出。

## 四、执行步骤清单（downhill）

- [ ] **Step 0 动作管线验证**（不依赖建模，可与 Step 1 并行）：Mixamo 取走/跑/跳/坐 3-4 动作（FBX）→ Blender 重定向到 VRM 骨架 → `.vrma` 导出 → nono-poc 播放（加装 `@pixiv/three-vrm-animation`）。**产出=骨架需求清单**（手指骨/裙摆分片骨/马尾骨/道具挂点/IK 目标是否需要）+ 工程问题暴露（root motion/脚部接地/脚滑）
- [ ] **Step 1 形体冻结**：比例定稿 + 脸部结构（眼窝/眼皮厚度/鼻唇立体）+ 眼球总成 + 眼睑重贴合，一批改完 → 冻结存档（.blend + 重导出 VRM，同步修名称元数据乱码）
- [ ] **Step 2 骨架规格定稿**：按 Step 0 需求清单一次规划额外骨骼（VRM1.0 允许标准人形外额外节点，须一次定清）
- [ ] **Step 3 服饰全套**：贴合建模（身体已冻结）+ Data Transfer 权重转移（骨架已冻结）+ springbone 物理 + 鞋袜配饰；删除被衣服遮挡的身体面
- [ ] **Step 4 动作库全量**：Mixamo 转制 + 自 K → 与服饰**联合迭代**穿模/权重（修的是权重与物理参数，不改服饰模型）
- [ ] **Step 5 表情资产+驱动层**：形状键 30-50 个 + 组合修正键（A+B 同激活时的修正形变）+ ARKit 52 命名体系（为面捕录制表情动画预留）；驱动层=表情分层叠加/时序曲线（快起慢落+表情泄漏）/视线微跳视/眨眼随机化/头部微动/口型 viseme（与驱动无模型依赖，可与 Step 3 并行）

每步完成 → nono-poc 渲染验收 + 截图归档 `05-美术设计/诺诺/` + README 登记。

## 五、动作 × 服饰交互规则

**返工触发表**（「加动作」本身不改服饰几何，只暴露权重问题）：

| 事件 | 后果 | 对策 |
|---|---|---|
| 身体形状改了 | 服饰几何失配，重新贴合 | 形体先冻结（Step 1） |
| 骨架改了 | 服饰权重要重刷 | 骨架规格先冻结（Step 2） |
| 加动作 | 暴露穿模/拉伸/塌陷 | 动作与服饰联合迭代（Step 4） |

**运动设定建议（需院长定款式方向）**：

- **两套服装**：日常套装=长裙（学院知性风）+ 运动套装=裤装或短装——一套长裙扛跑跳翻越物理上几乎必崩
- **运动发型=高马尾**：四发型体系（形象设计 §2.3）正好用上；及腰披发是翻越动作穿模重灾区
- **鞋跟高度固定并记录**：脚部接地动画依赖它
- **高领/围巾类**接触下颌颈部，须在脸型冻结后定版（或留余量）
