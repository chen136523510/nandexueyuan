## 一、核心立场：虚拟世界里"感知"问题是被消解的，不是被解决的

现实机器人"看"= 从像素反推世界状态（病态求逆：传感器→识别→SLAM→世界模型），贵且不准。诺诺的世界是 three.js 场景图+后端状态机，**每个物体的位置/状态/可见性本来就是渲染的输入数据**——直接读，不需要"看"回来。

但"看"有不可替代的价值：**表达而非决策**。读状态让她知道"下雨了"，只有看才能让她说出"晚霞把海染成橘子汽水的颜色了"。决策走状态，质感走视觉，两不相扰。

补充铁律：**感知的可信度 = 表达的丰富度，不 = 感知通道的保真度**。L2 事件触发"转头看向声源"的小脑动作，本身就是"她感知到了"的最强表现，零 VLM 成本——哪怕 L3 长期不上线，感知观感也能到八九成。

## 二、三层架构总览

| 层 | 类比 | 内容 | 成本 | 时机 |
|---|---|---|---|---|
| **L1 场景状态快照** | 本体感觉 | 结构化 JSON：时间（模糊时段）/天气/家具位姿/诺诺自身姿态（坐/站/位置/朝向/当前动作）/灯态 | 零 | 常驻（随每次 prompt 组装） |
| **L2 状态 diff 事件流** | 听觉/触觉 | 变化事件：`lamp_toggled` / `guest_enter` / `phase→night` / `weather→rain` + **自身动作结果回传**（"我坐下了"） | 零 | 事件驱动，有界队列 |
| **L3 视觉（VLM）** | 眼睛 | 按需截图→多模态模型描述→文本进上下文 | 低频 API 开支 | 事件驱动后置，依赖资产化 |

人也是这样感知的：走路不"看"自己的腿（本体感觉），听到响声才转头（事件驱动），看到美景才驻足凝视（高带宽视觉按需）。用同样的感知结构，她才像"住在房间里的个体"，而不是"装了传感器的木偶"。

## 三、L1 快照：形式澄清与设计（回应裁决 2、3）

### 3.1 形式：不是文件，不是渲染图——是内存对象→序列化函数

**澄清**：L1 与"原始渲染输入"无关（那是 L3）。场景状态在代码里是一等公民数据（roomApi / anchors / sitState / 光效档案），快照=从这些对象**现算**一个浓缩 JSON：

```js
// 形态示意（非实施代码）
roomApi.snapshot() →
{ "时段": "夜里", "天气": "雨", "位置": "书桌椅", "姿态": "坐",
  "灯": "开", "面前": "书桌(翻开的书)" }   // 目标 ≤200 token
```

- **单进程内**：就是函数调用+JSON.stringify，微秒级，零文件零 IO。
- **跨进程时**（大脑在后端 Node、3D 场景在浏览器——集成的真实形态）：**状态权威分两处**——环境全局量（时间/天气/弹幕事件）后端权威；诺诺身体与家具交互态（坐/站/位置/椅位）前端权威。前端经 WebSocket 上报身体态（同 nono_messages 的既有广播模式），**快照在后端拼装**后进 prompt。仍不是文件。
- 文件形式（状态落地 JSON 文件供读）只在跨进程调试时有用，正式链路不需要。

### 3.2 连续量分段感知（裁决 3 的设计落地）

原则：**连续量按语义节点离散化，不按数值均匀切**；精确值按需查询。

| 连续量 | 常驻快照里 | 语义事件（L2） | 按需查询（工具） |
|---|---|---|---|
| 时间 | 模糊时段（晨/午/黄昏/夜/深夜/黎明） | 时相切换事件（光效档案 7 时相的切换点就是天然事件边界，24h 连续轴已实现） | `get_time`（"看表"：需要精确时间才调） |
| 天气（未做，预留） | 当前天气档 | 天气**转变完成**事件（开始下雨/雨变小/雨停——光效档案 4 天气档+过渡 2~4s，过渡完成时发事件） | 无需（档位即语义） |
| 季节 | 当前季节 | 换季事件 | 无需 |

- "雨变小"的感知感 = 快照里天气档从"大雨"变"小雨"+一条事件，她下一次开口自然带出——**感知延迟是特性不是缺陷**：人不连续感知环境，诺诺"过一会儿才注意到"反而真实。
- 事件触发的措辞模板不硬编码（"天黑了"≠固定台词），事件只给语义事实，表达留给大脑。

### 3.3 Token 预算（有界设计，回应裁决 1、4）

常驻增量 ≤ ~350 token/次回复：快照 ≤200 + 未消化事件 ≤8 条 ~150。变化内容放 prompt 尾部（DeepSeek Context Caching 实测命中率 72% 的既有结构不破坏：稳定 system 前置、快照与事件进尾部变化区）。

## 四、L2 事件流：有界工作记忆（回应裁决 4）

**事件流 ≠ 常驻上下文**。生命周期三段：

```
产生 → 未消化队列（有界，容量 N≈8） → 随回复被"注意"消耗 → 固化进 NonoMemory → 出队
```

- **消化**：事件随下一次回复进入 prompt，被大脑回应后标记 consumed，走既有记忆固化管线（NonoMemory 三因子+mem0 式固化）成为长期记忆，从队列清除。
- **溢出压缩**：队列将满，最老一批未消化事件压成一行摘要（"19:00–19:20：3 人进出，开始下雨"）——摘要进记忆系统可检索，不占常驻上下文。
- **自身动作回传**：小脑执行结果也发事件（`sat_down` / `lamp_toggled_by_me`），大脑由此闭环知道自己动作的后果——这是"大脑→小脑→感知→大脑"闭环的最后一环。
- 结果：上下文占用**有上界**，长期积累全部进记忆系统按需检索——膨胀问题在架构上不存在。

## 五、L3 视觉：按需拍照，依赖资产化（回应裁决 5）

- **形式**：非常驻摄像头。触发时机=大氛围点（日落/初雪/换季）或被问"你看到了什么"。技术：three.js 相机（可绑 head 骨=诺诺第一人称）渲一帧 offscreen canvas → toDataURL → 多模态模型描述 → 文本进上下文。工程零障碍，唯一约束是调用频率红线。
- **依赖关系确认（院长裁决）**：L3 输出质量=场景资产质量。白盒阶段读了也是色块——**L3 排在资产化之后是天然顺序，不是浪费**。
- **模型选型（成本纪律内）**：诺诺大脑主体（DeepSeek 文本 LLM，裁决 6）与视觉通道**可分离**——DeepSeek 官方 API 当前无多模态版；视觉旁路届时配多模态模型（免费额度系或本地小模型），不影响主体链路。若未来 DeepSeek 出原生多模态或院长指定原生多模态模型，合回一路即可（院长：原生多模态下开支可接受）。

## 八、业界调研印证与修订登记（2026-10-09）

> 调研全文：[虚拟世界LLM感官感知架构业界调研](../00-调研/01-技术/虚拟世界LLM感官感知架构业界调研.md)。**总体裁定：三层设计获业界全面印证（Convai 商业实现同构/Generative Agents 学术原型/Mindcraft 开源实证），无需推倒**。四条增强修订：
> 1. **L1 增补节流参数**：前端身体态上报参考 Convai 的 0.5s 批量/3s 上限节流。
> 2. **L2 增补全量落盘**：事件出队前全量写记忆库（哪怕未消化），落盘与消化解耦（Mindcraft 防丢失保险）。
> 3. **L3 增补标注式视觉**：诺诺"看"时截图叠加物件名/状态标注（Set-of-Mark 思路）再给 VLM，标注优于裸图（VisualWebArena，ACL 2024）。
> 4. **新增状态驱动自主行为层**：L1+L2 兼作 idle 自主决策触发器（self-prompting，Voyager/Mindcraft 先例）——"30 分钟无弹幕→打瞌睡/去看书"的实现路径；快照适配器预留 `onIdle` 事件位。
>
> 另：Neuro-sama 感知机制无一手技术文档，不作为设计依据；参照系以 Convai/Generative Agents/Mindcraft 为准。
