## 一、30 秒版本（先读这个）

**一句话**：诺诺的每个动作，最终都是「**平移 / 弯曲 / 旋转**」三种基元操作的组合；组合结果写成带名字的**配方**；LLM 大脑用**语义**调用配方（说"失落"而不是碰关节）；引擎保证**随时可打断**；呼吸眨眼作为**心跳层**永远在跑。

```
大脑(nonoAgent·LLM)──语义调用──▶ 小脑(本文)──每帧驱动──▶ 身体(VRM模型)
```

**三个关键词**：基元（原子操作）· 配方（提前编排的组合）· 打断（动作中仍在思考）。

## 二、全局架构图

```
┌─────────────────────────────────────────────────────────────┐
│ 大脑  nonoAgent（LLM，已有，见记忆系统设计）                    │
│   感知弹幕 → 思考 → 产生情绪状态与意图 → 语义调用               │
│   「她感到伤心」 →  调用〔失落〕 intensity=0.7                 │
└──────────────────────────┬──────────────────────────────────┘
                           │ 语义调用（异步，不阻塞文本流）
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 小脑  动作运行时（本文要造的东西）                              │
│                                                             │
│  语义层   情绪→行为映射表：〔失落〕= 失落表情+垂肩配方+呼吸变慢   │
│  配方层   配方库（带名字的基元序列 JSON）；clip=配方的编译产物    │
│  基元层   平移 / 弯曲 / 旋转（+镜像·幅度·循环 修饰符）           │
│  引擎     补间混合 · 随时可打断（150ms 滑向新目标）· 安全点      │
│  心跳层   呼吸 · 眨眼 · idle 微晃（常驻，永远在跑，被临时覆盖）   │
└──────────────────────────┬──────────────────────────────────┘
                           │ 每帧驱动（rAF 内，毫秒级）
                           ▼
┌─────────────────────────────────────────────────────────────┐
│ 身体  VRM 模型（v7 贴片眼定版，poc/nono-poc 已跑通）            │
│   Humanoid 骨骼（旋转/位移驱动）+ morphTarget（表情）           │
│   + SpringBone（头发物理，自动跟随不归本引擎管）                 │
└─────────────────────────────────────────────────────────────┘
```

**数据流只有两条**：下行=调用（大脑→小脑→身体）；上行=事件（配方播完/被打断时回调大脑，供其决策下一步）。

## 三、术语表（6 个词讲完整个系统）

| 术语 | 一句话定义 | 例子 |
|---|---|---|
| **基元** | 骨骼上的原子操作，只有三种：平移/弯曲/旋转 | 右大臂绕 y 轴旋转 -60°，历时 0.5s |
| **配方** | 提前编排好的基元序列，带名字和参数，是动作的存储单位 | 〔背手〕〔耸肩〕〔失落〕 |
| **clip** | 配方的编译产物——动捕数据经编译器转成基元序列，接口与手写配方完全一致 | 走路、舞蹈（院长定性：clip 就是若干基元和参数的组合） |
| **语义调用** | LLM 按名字+参数调用配方，永远不碰关节角度 | `{action:"wave", intensity:"subtle"}` |
| **心跳层** | 常驻循环配方（呼吸/眨眼/idle 微晃），永远在跑，上层动作只是临时覆盖 | 现有 PoC 的呼吸眨眼代码直接迁入 |
| **打断** | 任何动作执行中可被新指令/大脑自身/外部事件中断，150ms 平滑滑变，无残姿 | 挥手挥到一半放下手来回应弹幕 |

## 四、分层设计

### 4.1 基元层（原子操作，最小词汇表）

| op | 骨骼机制 | 典型关节 | 参数 |
|---|---|---|---|
| `rotate` | 球窝关节自由旋转（3 自由度） | 肩/髋/腕/踝/脊柱节段 | bone, axis(x\|y\|z), deg, dur, easing |
| `bend` | 铰链关节受限旋转（1 自由度，**引擎内建角度限位**，弯错方向自动钳制） | 肘/膝/颈屈伸 | 同上 |
| `translate` | 根骨骼/髋部位移（位移类动作的载体） | hips | axis, offset(m), dur |
| `keyframes` | 密集关键帧通道（**动捕编译专用**，见 §6.2） | 任意 | track 数据 |

**修饰符**（不是新基元，是配方/条目上的参数）：

- `mirror`（配方级）：左右镜像复用——背手写右手版，左手自动镜像
- `intensity`（配方级）：幅度整体缩放 0~1——**这就是"清冷人格"的执行层**（清冷=intensity 上限约 0.6）
- `delay`（条目级）：延迟启动，编排出先后时序
- `loop`（条目级）：循环次数；`-1`=无限循环直到被打断（抖腿用）

### 4.2 配方层（动作的表示与存储）

配方 = JSON 文件，完整 schema：

```json
{
  "id": "hands_behind_back",          // 英文标识（工具调用用）
  "label": "背手",                     // 中文描述（人看）
  "version": 1,
  "intensityDefault": 0.8,
  "interruptible": true,              // 默认全可打断；坐下/起立类设 false 或用安全点
  "safePoints": [1.2],                // 秒——安全点时刻表（此处之后打断不悬空）
  "mirrorable": true,
  "channels": { "expression": null, "breath": null },   // 配方可顺带触发其他通道
  "sequence": [
    { "op": "rotate", "bone": "rightUpperArm", "axis": "y", "deg": -60, "dur": 0.5 },
    { "op": "bend",   "bone": "rightElbow", "deg": 95,  "dur": 0.5 },
    { "op": "rotate", "bone": "leftUpperArm", "axis": "y", "deg": 55, "dur": 0.5, "delay": 0.3 },
    { "op": "bend",   "bone": "leftElbow", "deg": 85,  "dur": 0.4, "delay": 0.3 }
  ]
}
```

（角度数值为示意，实际在 Blender/HUD 调参定版。）

**关键性质——配方即路径控制**：手臂绕到背后的运动路径由 keyframe 顺序决定。先外旋再后摆=手臂划安全弧线绕过去；直插过去=穿腰。**穿模治理在配方编排时就完成了大半**（详见 §七）。

### 4.3 语义层（LLM 的接口）

**情绪→行为映射表**（emoMap，配置文件）：LLM 只表达内部状态，不碰关节：

```json
{
  "失落": {
    "expression": "Fcl_ALL_Sorrow",
    "recipes": [ { "id": "head_low_shoulders_drop", "intensity": 0.7 } ],
    "breath": { "rate": 0.6, "depth": 0.8 },
    "blinkRate": 0.5
  }
}
```

**调用形态两步走**（与"直播间集成推后"裁决对齐）：

- v1（现状，PoC 阶段）：文本流内 `(动作:xxx)` 标记
- v2（Phase C）：nonoAgent 工具调用 `nono_act(action, intensity, duration_s, interruptible)`，动作与表情随情绪一次调用多通道齐发

**人格参数表**（personality preset，配置文件）：intensity 上限、各配方使用频率倾向、微动作密度——清冷毒舌 vs 其他性格的差异全部落在这张表，换人格=换配置不换引擎。

### 4.4 心跳层与表情通道

- **心跳层** = 常驻循环配方：呼吸（已有代码迁入）、眨眼（已有）、idle 微晃（重心小幅摆动，新增）。永远在跑；上层配方只临时覆盖相关骨骼，动作结束心跳自动回归——**诺诺永远是活的，不存在静止帧**
- **表情通道** = morphTarget（Fcl_ALL_* 全套已有），与身体配方**并行独立**：动作管骨骼，表情管脸，可任意叠加（〔害羞〕= 挡脸配方 + happy 表情）

## 五、运行时引擎（小脑的机械结构）

### 5.1 执行模型：配方 = 可取消的程序

每条基元条目是一个**补间（tween）**：从骨骼当前值出发，历时 dur 滑向目标值。配方执行器按 delay/duration 调度这些 tween，播完发事件回调。

**平滑性的数学保证**：tween 永远"从当前值出发"——所以打断天然无跳变：取消未启动的 tween，正在进行的用 150ms 滑向新目标（或中立姿势）。不存在"残姿"问题。

### 5.2 中断机制（本架构的核心红利）

| 中断源 | 行为 |
|---|---|
| 新语义调用（抢占） | 当前配方 150ms 滑向新配方首帧；若当前是关键过渡（坐下等）且未到安全点，先快进到最近安全点再切 |
| 大脑自中断 | 大脑调用 stop/change——**做动作时仍在思考、可决定不做了**，这是"诺诺是个体不是木偶"的直接体现 |
| 外部事件（弹幕等） | 经大脑决策后走上面两条路径，引擎不直接听外部 |
| 心跳层 | 永不打断别人也不被打断（只被覆盖/回归） |

### 5.3 延迟预算（分级，红线：实时期优先）

| 层 | 预算 | 说明 |
|---|---|---|
| 心跳层 | 每帧本地，零额外延迟 | rAF 内直接驱动 |
| 基元引擎 | <1 帧（毫秒级） | 调用即播，无任何 IO |
| 语义调用 | LLM 吞吐异步 | 动作不阻塞文本流；**禁止 LLM 管逐帧**（宇树启示：反射级本地、认知级云端，见调研 §六） |

### 5.4 与现有 PoC 代码的衔接

- 基座：`poc/nono-poc/`（three 0.186 + three-vrm 3.5.5，v7 贴片眼定版，200FPS）
- 直接复用：expressionManager（表情）、呼吸眨眼（迁入心跳层）、SpringBone（独立运行不归引擎管）
- 新增模块（建议命名）：`poseDriver.js`（骨骼补间引擎）/ `recipeExecutor.js`（配方调度+打断）/ `heartbeat.js`（常驻层）/ `emoMap.json` + `recipes/`（数据）
- 必守铁律（bug-log 沉淀）：挂骨对象静息基准存**局部参考系**（BUG-084）；VRM 表情 bind 只认 `Fcl_ALL_*` 组合键、glTF morphIndex=key_blocks-1（BUG-085/086）；遮挡环境复验防 rAF 节流假阴性（BUG-087）
- Mixamo `?anim=` 验证路径保留作回归基线，不删除

## 六、动作资产工作流（配方从哪来）

四条生产线，产出统一为配方 JSON：

| 生产线 | 适用 | 工具 |
|---|---|---|
| 手写 JSON | 上半身简单配方（背手/耸肩/歪头/挥手） | 直接写，HUD 测试台调参 |
| Blender 编排导出 | 复杂上半身编排 | Blender 摆姿势→导出工具转配方 JSON（Phase B 建） |
| 动捕编译（=clip） | 步态/舞蹈/杂技级 | 摄像头表演→GVHMR→FBX→**编译器**转配方（Phase B 建） |
| CC0 改编 | 补充量 | Quaternius 库 FBX 走同一条编译线 |

**入库 gate（所有生产线共用）**：①**运动路径采样**（配方播放全程逐 ~70ms 采手/足世界坐标，对躯干圆柱体积判定穿交——**"埋入体内"的穿模从外部任何视角都不可见，静态截图抓不住，BUG-090**）→ ②**六视角视觉自查**（正面/背面/左右侧/后 3-4/关节特写）→ ③**关键骨骼位置数值断言**（手/肘锚点 vs 目标区间）→ ④Blender 穿模体检脚本逐帧测距（动捕编译配方必检）→ ⑤骨架健康检查 → ⑥配方 JSON schema 校验 → 入配方库。

**⚠️ 轴约定实测（2026-10-05 Phase A 沉淀，手写配方必读）**：引擎的偏移是"叠加在静息姿势上的欧拉分量"，euler-add 实测语义=**RY 最外层（世界系水平摆）/RX 中层/RZ 最内层（随静息系抬沉）**——不是世界轴直转，三轴复合时互相改写效果。单轴速查（左臂，右臂 y/z 反号）：**x+ =手向后摆**、y+ =内旋/水平后收（大角度=前臂绕到体后的主机制）、z+ =上抬（z- =下沉+过中线内收）。四条铁律：①**父骨已旋转后，子骨偏移在父系里生效**——复杂姿势按"先子后父"编排；②**配方参数用矩阵探针求解**：引擎里直接设 euler 组合→量手部世界坐标→锚定目标位置反解，禁止靠正面截图猜深度（v1~v6 六轮误读教训）；③姿势目标用"三维手位锚点"表达（如背手=脊柱旁·腰带高·体后）；④动作要领查权威来源（[常见动作执行要领与生物力学调研](../00-调研/01-技术/常见动作执行要领与生物力学调研.md)），不凭直觉编角度。

## 七、穿模治理（设计内建，三层）

1. **事前路径控制（主手段）**：配方编排即避让——keyframe 顺序决定运动路径，划弧不直插（§4.2 性质）
2. **体检 gate**：Blender 逐帧采样手尖/脚尖/髋/发饰挂点对模型 mesh 的距离，超阈值报警修帧——**只对动捕编译配方必检**（手写配方路径本身可控），作为入库强制关卡
3. **运行时兜底（明确取舍）**：**不做**实时网格自碰撞——动漫渲染管线通行做法，算力不值；轻微穿插靠 SpringBone/裙物理骨缓解，大幅穿插在 gate 拦截

## 八、分期施工计划（基础先行，细节后补）

### Phase A：基元内核（下一步，可直接开工）
`poseDriver` 骨骼补间引擎 + `recipeExecutor`（调度/打断/安全点）+ 心跳层迁移 + HUD 测试台（粘贴配方 JSON 即播/打断按钮）+ 手写 3 配方（背手/耸肩/歪头）验证。
**验收**：①HUD 粘贴 JSON 即播免刷新 ②三配方正确驱动 ③播放中切另一配方 150ms 平滑无残姿 ④播放中停→回中立姿 ⑤呼吸眨眼全程不断 ⑥200FPS 不掉。

### Phase B：配方库 + 资产生产线
5~10 配方入库（清单沿用[动作库规划](诺诺动作库规划.md) §二按基元改写）+ Blender 导出工具 + 动捕编译器 v1（一段 Mixamo FBX 编译成配方成功播放）+ **穿模体检脚本上线**。
**验收**：四条生产线各出 1 个合格配方过 gate。

### Phase C：语义接入
情绪映射表 v1（3~5 情绪）+ nonoAgent 工具 schema 定稿 + 本地测试台演示（模拟弹幕→情绪→动作链→自中断）。**不动直播间**（10-01 裁决：集成推后，届时另行裁决）。

> 优先级裁决（2026-10-05）：**基元系统 > 穿模细节修补**——基元系统本身是穿模根治手段（§七第 1 条），体检 gate 在 Phase B 资产产生前上线即可。
