## 一、设计哲学（院长定调，全系统的宪法）

1. **真人脑回路建模**：独处时做自己的事（读书/发呆）；与人互动时瞬间调出对方的记忆（整档加载，切人即切档）；多人场景理解他人之间互动传递的信息/思想/感情。
2. **不靠上下文规模，靠工程极致化**：大模型上下文规模我们无法优化，可控的是记忆管理工程——把每 token 的效用发挥到极致（与 MemGPT"LLM 当 CPU、上下文当内存"同一哲学）。
3. **避免屎山**：历史互动精确增减，不无脑全量；有容量预算；有审计；可测试。
4. **实时性红线**：任何记忆机制不得显著增加回复延迟（热路径零 LLM 摄取）。
5. **读空气**：知道群体氛围/习惯/倾向，**可以不跟随，但需要知道**。
6. **记忆自然成长**：不着急灌，慢慢培养。

## 二、记忆全景：四层

```
┌─ 主存档（诺诺自己，1 份）────────────────────┐
│  自我认知（性格基线，静态——人设一部分）        │
│  生活日志（最近在看什么书/做了什么，滚动归并）  │
│  观点心境（她表达过的看法、情绪倾向）          │
├─ 用户存档（× 21，每成员一份）────────────────┤
│  基础信息（名字/外号/身份，低频更新）          │
│  关系画像（对此人整体认知，可重写段，≤300字）  │
│  互动历史（分层条目，见生命周期）              │
├─ 群像层（读空气，1 份）──────────────────────┤
│  梗词典（每个梗：谁首创/谁在用/含义/场合）     │
│  关系网（谁和谁熟/有无过节，简版）             │
│  氛围基调（当前社区情绪倾向，定期重估）        │
├─ 公共流（原始事实层）────────────────────────┤
│  nono_messages 直播流（带 subject/reply_target）│
│  公共事件（跨用户的社区大事）                  │
└──────────────────────────────────────────────┘
```

群像层单列（不并入公共记忆）的理由：GroupMemBench 证明说话者锚定和词汇差异在"泛公共池"里会被平均化掉——梗和关系网必须以结构化条目存在，不能靠检索散消息还原。集体记忆研究（arXiv:2512.10166）同时证明：共享层必须挂在诺诺的个体记忆（主存档/用户存档）之上才有效。

## 三、数据模型（穷人版 bi-temporal + 溯源）

所有记忆条目统一元字段（SQLite 即可，无需图数据库）：

| 字段 | 说明 | 来源依据 |
|---|---|---|
| `scope` | `user:{id}` / `group` / `self` | AIM：**隔离做在检索层（WHERE scope），不做在 prompt 嘴上**——对 A 说话时候选集里物理上不存在 B 的私有条目（防 persona confusion） |
| `t_valid` / `t_invalid` | 事实成立区间 / 失效时刻 | Zep bi-temporal 穷人版；**旧事实标记失效永不物理删除**，可查任意历史时刻的世界状态 |
| `invalidated_by` | 指向推翻它的新条目 id | 溯源链 |
| `source_msg_id` | 回溯到原始直播流消息 | Graphiti episodes 层；"诺诺记错了"时可回查原始聊天记录（社区信任基础） |
| `confidence` | 置信度（传闻低/亲历高） | Manufactured Confidence：A 说的八卦不能固化成诺诺的同级确信 |
| `hit_count` | 被检索命中次数 | MemSIF：**使用频率才是固化信号**——ActiveFact 被"多来源支撑且反复查询"才晋升长期 |
| `salience` | 显著度 1-10 | Generative Agents importance；淘汰依据 |

## 四、生命周期（精确增减，防屎山核心）

### 4.1 摄取（热路径零 LLM）
直播流消息只追加原始记录+标记，**buffer 批处理**（攒 ~1k token 或触发回复时顺带）——Memobase 模式，保实时性。每条事实**必须带 subject（谁说的）与 reply_target（对谁说/回复谁）**——GroupMemBench 的最大教训：说话者结构被压缩掉是群聊记忆失效之首因。

### 4.2 固化（双层闸门）
- **写入闸门**：LLM 单遍打分（重要性≥阈值才入库，寒暄/琐事拦掉）——MemGauge：写入准入有阈值式风险跳变，宁缺毋滥；
- **晋升闸门**：ActiveFact（临时条目）只有 hit_count 达标+多来源支撑才晋升为持久记忆——解决"写入时判重要性不可靠"（MemSIF 核心洞察）。

### 4.3 更新（patch 保守化）
新旧矛盾时：**LLM 只判矛盾（输出 bool+理由），旧条目标 `t_invalid` 指向新条目，不物理改写**——TrustMem+Mem0 v3 共同结论：覆盖式更新是主要故障源（遗漏/破坏/幻觉三类错误）。原有的 ADD/UPDATE/MERGE/DELETE/PROMOTE 全权 patch 收窄为：
- ADD：新增条目；
- INVALIDATE：标失效（带理由与指向）；
- MERGE：同话题归并（仅整理 agent 可执行，见 4.4）；
- PROMOTE：晋升/沉淀（画像段更新——唯一允许"重写"的段）。

### 4.4 整理（"诺诺睡觉"——Letta dreaming 穷人版）
**双 agent 分权**：对话中的诺诺**只读**记忆；夜间/闲置整理 agent（node-cron 触发）独占编辑工具，做四件事：
1. 压缩冷记忆（同话题归并，90 天未触达且低显著度的情节条目降级）；
2. 反思（主存档观点心境更新+用户存档画像段重写——阶段反思重申性格基线，防漂移）；
3. 群像层重估（梗词典增删、氛围基调刷新）；
4. **预计算**（sleep-time 论文核心收益：预判明天谁可能来聊什么，提前备好 learned context，把 test-time 计算省 5x）。
"独处过日子"与"整理记忆"共用同一调度——院长脑回路模型中"一个人自己生活"的工程对应。

### 4.5 淘汰
容量预算硬上限触发：用户存档 ≤800 token 级、主存档 ≤500、群像层 ≤300。超限从最低 salience×recience 的失效/陈旧条目开始降级（不物理删，移出注入候选）。

## 五、注入策略（注意力管理十条，全部有调研依据）

1. **相关性硬过滤，宁少勿多**：1 个"看似相关但不含答案"的条目 = 准确率 -19%（Power of Noise, SIGIR 2024）——低于阈值宁可不注；
2. **检索查询携带当轮问题语义**，不按画像泛检索（Context Rot：**"与用户相关但不回答当下问题"是最恶劣的干扰源**——精确对应"记忆把注意力带偏"的担忧）；
3. **位置**：记忆与档案放 prompt 前部，**当前问题与指令放末尾**（U 型曲线 + 指令后置 +9.7 BLEU）；
4. **规模**：检索条目 3-5 条硬上限；用户存档整档注入（存档本身是压缩态）但总注入控制在一屏量级（300 token 级聚焦输入全面优于大而全）；
5. **分层**：小核心常驻（关系画像+基础信息）+ 细节按需（互动历史检索）；
6. **措辞框架**："以下为背景参考，仅在与当前话题相关时自然使用，否则忽略"+ 结构化标签包裹（GSM-IC 证实有效）；
7. **时间戳与权威性随条目注入**（"（上周他说）"），新事实可覆盖旧印象（CMI：缺权威线索时旧记忆压制新事实）；
8. **写入门槛**（见 4.2）；
9. **工具式 recall 后置二期**（agent 自主查记忆）——agentic search 延迟高于预载，与实时性红线冲突，先混合策略；
10. **上线前自测**：LongMemEval 式"拒答/知识更新"两维探测（该答不答=被旧记忆带偏；该更新不更新=记忆陈旧压制当下）。

**注入模板**（跟丘序明聊天时）：
```
[system] 人设(静态) + 主档近况(她的今天,低频变) + 群像层摘要(读空气,≤300字)
         + 【当前对话者档案·丘序明】基础信息+关系画像(常驻小核心)
[user]   直播流(带其他发言者的一行式认知) + 按当轮问题检索的互动历史(≤5条,带时间戳) + 新消息
```
多人场景：流内其他发言者附 one-liner（"丘序明（爱考公，说话直接）刚说：…"）——群像层的关系网提供素材。

## 六、读空气（群像层专项设计）

- **来源**：整理 agent 定期（每日/每 N 天）从公共流+各用户存档聚合提炼；
- **内容**：梗词典（结构化：梗/首创者/使用者/含义/场合）、关系网（亲疏简图）、氛围基调（近期的社区情绪——考试季焦虑/喜庆/争论期）；
- **注入**：轻量常驻（≤300 字），**措辞给予 agent 主体性**："以下是社区的氛围认知。你可以有自己的态度，不必迎合；但这些是大家在意的东西。"——院长的"可以不跟随，但需要知道"的直接实现；
- **更新触发**：新梗出现（流中检测到高重复新词）、关系变化（互动模式突变）、大事件后。

## 七、工程纪律（防屎山四条+两条）

1. 容量预算硬上限（超限强制压缩管线）；
2. patch 保守化（只 ADD/INVALIDATE/MERGE/PROMOTE，物理重写仅画像段）；
3. 每次更新留审计（操作+理由+溯源，可回溯调试）；
4. 管线纯函数化（输入旧档+新互动 → 输出 patch），**可单元测试**——长期不退化的关键；
5. 检索 = FTS5 + 暴力余弦双路（20 人规模毫秒级，零新依赖——GroupMemBench 背书 BM25 够强）；
6. 全部纯 SQL/SQLite 实现，不引入向量库/图库/消息队列。
