# 可视化剧情编辑器选型调研

> 调研时间：2026-08-19（白机）
> 调研人：AI（白机，三路子 Agent 分治：通用节点图框架 / 剧情专用编辑器 / GitHub 现成项目，主线程交叉验证）
> 背景：R-034 剧情脚本可视化编辑器，院长 2026-08-19 裁决选定可视化编辑器路线（放弃 DSL/表格驱动），归属新模块「岁月史书」。德塔视觉小说剧情节点格式为自定义 JS 对象 `{id, type, text, speaker, background, characters, next, choices, effects}`，引擎 6 种节点类型（dialogue/choice/condition/event/input/end）。需找现成开源框架构建可视化分支对话树编辑器，尽量不重复造轮子。技术栈 Vue 3 + Vite + Pinia。
> 关联文档：`.ai/handoff.md`、`src/visualnovel/engine/types.js`（节点类型定义）、`src/visualnovel/data/scripts/README.md`（现有文案分离架构）

## 一、核心结论（先看这个）

1. **GitHub 上不存在可直接 fork 或 npm 安装的「Vue 3 可视化对话树编辑器」成熟项目。** 三路调研交叉验证：基于 Vue Flow 的对话编辑器搜索结果为 0 个高星项目；剧情专用编辑器（Yarn/Ink/Twine）要么是桌面应用，要么 GPL 协议有传染风险，要么数据格式（HTML/.yarn/.ink）与德塔 JS 节点对象不匹配；npm 上没有成熟的可视化分支对话树编辑器组件。

2. **最优路径：Vue Flow 自建 + 参考现有数据模型。** `@vue-flow/core`（MIT，6.8k★，周下载 34 万，Vue 3 原生组件）做节点画布，参考 Arcweave/Chat Mapper 的 JSON 结构设计节点 schema，参考 dialogbench/tuesday-js 的节点类型设计。德塔剧情数据本身就是 JSON，Vue Flow 的 nodes/edges 模型与之天然映射。存量 474 节点零迁移风险。

3. **框架选型 Top 3**：
   - **Vue Flow**（首选）：Vue 3 原生，MIT，活跃维护，节点/边/连线全用 Vue 组件定义，与 Pinia Store 天然响应式联动
   - **Baklava.js**（次选）：Vue 3 原生，自带侧边属性面板，开箱即用程度最高，但社区规模小
   - **Rete.js**（备选）：框架无关 + Vue 渲染插件，功能最完整（撤销重做/数据流引擎），但学习曲线高，对对话树场景能力过剩

4. **数据结构参考 Top 3**：
   - **Arcweave JSON**：elements+connections+branches+conditions+variables，最完整，可直接映射德塔节点
   - **Chat Mapper JSON spec**：公开 spec + MIT 解析器，drag-and-connect 功能集是自研编辑器的功能清单模板
   - **Yarn Spinner 脚本->JSON 双形态**：脚本编译范式可提供「类 Yarn 脚本」作为可选输入模式

5. **明确排除**：Twine（GPL-3.0 传染风险）、GoJS（商业收费）、Drawflow/Litegraph.js（停更近 2 年）、JointJS 开源版（属性面板在商业版）、React Flow/Flume（React 生态不兼容 Vue）、桌面应用（inky/Crochet/articy/TyranoBuilder）

### Top 3 推荐理由

**1. Vue Flow（首选）**：Vue 3 原生组件库（非 wrapper），MIT 协议，周下载 34 万且持续维护；节点/边/连线全部用 Vue 组件定义，与项目 Pinia Store 天然响应式联动；官方示例中就有 chatbot/对话树场景，与德塔 6 种节点类型（dialogue/choice/condition/event/input/end）映射直接--choice 节点的多出口连线就是标准 edge 模型。代价：属性面板需自建（官方推荐 node-sidebar 模式），但德塔节点属性结构简单，用普通 Vue 表单即可。来源：[github.com/bcakmakoglu/vue-flow](https://github.com/bcakmakoglu/vue-flow) ｜ [vueflow.dev](https://vueflow.dev)

**2. Baklava.js（次选）**：Vue 3 原生（@baklavajs/renderer-vue），自带侧边属性面板与节点内嵌字段，开箱即用程度最高；MIT 协议。代价：社区规模（2 千 star / 5 千周下载）明显小于 Vue Flow，遇到边角问题需自己啃源码。来源：[github.com/newcat/baklavajs](https://github.com/newcat/baklavajs)

**3. Rete.js（备选）**：框架无关引擎 + Vue 渲染插件，功能最完整（含 area-plugin/minimap/数据流引擎/撤销重做），12.2k star、7.2 万周下载。代价：包拆分细，v2 重构后学习曲线明显高于 Vue Flow；节点 UI 要遵循 Socket/Port 抽象，对对话树场景能力过剩。来源：[github.com/retejs/rete](https://github.com/retejs/rete) ｜ [retejs.org](https://retejs.org)

> **注**：用户最初提到的「Bekit」在 npm 和 GitHub 上均不存在为 Vue 3 节点编辑器的项目。发音最接近且确为 Vue 3 原生节点编辑器的是 Baklava.js（newcat/baklavajs），本报告以它代替参与对比。

## 三、剧情/对话专用编辑器调研

> 调研维度：剧情/对话/视觉小说专用的开源或商业编辑器工具，评估能否直接嵌入 Web 前端或参考其数据结构

### 逐工具分析

#### 1. Yarn Spinner + Yarn 编辑器

| 维度 | 结论 | 来源 |
|---|---|---|
| 开源/商业 | 核心编译器开源；Unity 集成商业 | [YarnSpinner GitHub](https://github.com/YarnSpinnerTool/YarnSpinner) |
| 协议 | 核心 MIT | GitHub API |
| Web 版 | 有官方在线版 try.yarnspinner.dev，但无嵌入式 SDK | [docs.yarnspinner.dev](https://docs.yarnspinner.dev/) |
| 导出格式 | .yarn 脚本（screenplay-like），可编译为 JSON | docs.yarnspinner.dev |
| 分支树可视化 | YarnClassic 有（类 Twine 节点图）；官方 Yarn 2.x 走 VS Code 扩展 + 在线编辑器，非节点连线式 | [YarnClassic README](https://github.com/blurymind/YarnClassic) |
| 社区活跃度 | 核心 2.8k★，2026-08 活跃 | GitHub API |
| npm 运行时 | yarn-bound（ISC,35★）、bondage.js（MIT,62★） | npm registry |

**关键发现**：YarnSpinnerTool 组织下无独立 Web 编辑器仓库。官方编辑器演变为 VS Code 扩展（已 archived）+ 在线版。第三方 YarnClassic（MIT,546★）是 Yarn 1 语法编辑器，不兼容 Yarn 2，无 npm 包。

#### 2. inkle's Ink + inky 编辑器

| 维度 | 结论 | 来源 |
|---|---|---|
| 协议 | MIT | [inky README](https://github.com/inkle/inky) |
| Web 版 | **仅桌面**（Electron），无 Web 版 | inky README |
| 分支树可视化 | **不支持**，仅语法高亮+实时错误+播放预览 | inky README |
| 运行时 | `inkjs`（MIT,648★,2026-08 活跃），API：`new inkjs.Story(json)`->`Continue()`->`currentChoices`->`ChooseChoiceIndex(i)` | [inkjs README](https://github.com/y-lohse/inkjs) |

**关键发现**：ink 生态是「脚本语言 + 编译 JSON + 多语言运行时」的成熟范式，运行时 inkjs 可直接嵌入 Vue 3，但编辑器 inky 是桌面 IDE 无可视化节点连线。若接受「纯脚本式写剧情」而非「拖拽节点连线」，ink + inkjs 是最低成本方案。

#### 3. Twine

| 维度 | 结论 | 来源 |
|---|---|---|
| 协议 | **GPL-3.0** | [twinejs GitHub](https://github.com/klembot/twinejs) |
| Web 版 | 有 Web 版 twinery.org，无嵌入式 SDK | twinejs README |
| 导出格式 | HTML（story format 可插拔） | twinery.org |
| 分支树可视化 | **支持**，核心功能 | twinery.org |
| npm 包 | **无**，npm install 仅用于本地构建 | twinejs README |

**关键发现**：Twine 是「Web 版可用 + 节点连线可视化 + 开源」三合一的最接近项，但 **GPL-3.0 协议对德塔有传染性风险**，且数据格式为 HTML 非 JSON，与德塔自定义 JS 节点对象不匹配。仅作产品形态参考。

#### 4. Arcweave

| 维度 | 结论 | 来源 |
|---|---|---|
| 开源/商业 | **商业 SaaS** | [arcweave.com](https://arcweave.com) |
| 导出格式 | **JSON**（Schema 公开：boards/elements/connections/branches/conditions/components/attributes/variables/locales） | [docs.arcweave.com/integrations/json](https://docs.arcweave.com/integrations/json) |
| 分支树可视化 | **支持** | arcweave.com |
| 对接方式 | REST API（Bearer Token，端点 /api/{hash}/json）返回标准 JSON | [docs.arcweave.com/integrations/web-api](https://docs.arcweave.com/integrations/web-api) |

**关键发现**：Arcweave JSON 结构是**最值得参考的数据模型**：elements（含 outputs 连接 ID、components、attributes）+ connections（sourceid/targetid/sourceType/targetType）+ branches（if/elseIf/else 条件）+ conditions + variables。这套结构与德塔节点可建立映射：element->node、outputs/connections->next、branches/conditions->choices 的条件分支、components/attributes->effects。

#### 5. Chat Mapper

| 维度 | 结论 | 来源 |
|---|---|---|
| 开源/商业 | **商业 SaaS**（数据层面开放：public JSON spec + MIT 参考解析器） | [chatmapper.com](https://www.chatmapper.com) |
| Web 版 | Web 版 + 桌面版都有 | chatmapper.com |
| 导出格式 | JSON/XML/Yarn/Twine/articy/SCORM | chatmapper.com |
| 分支树可视化 | **完全支持**：drag-and-connect canvas，含角色节点/选项/分组/变量/条件/跨对话链接/自动布局/撤销/批量多选 | chatmapper.com |
| 定价 | Free $0（1 编辑者/3 项目/300 节点）；Creator $19/月 | chatmapper.com |

**关键发现**：Chat Mapper 是商业工具中数据开放度最高的，其 drag-and-connect canvas 功能集是德塔自研编辑器的**功能清单模板**。强烈建议参考其 JSON spec 设计德塔的节点 schema。

## 五、综合对比与选型决策

### 三条路线评估

| 路线 | 代表 | 优点 | 缺点 | 适合德塔？ |
|---|---|---|---|---|
| **A. 直接嵌入现成编辑器** | tuesday-js（iframe）/ Twine（iframe） | 零开发成本 | 数据格式不匹配需适配层；GPL 风险（Twine）；iframe 与 Vue Store 通信复杂 | ❌ 不推荐 |
| **B. fork 现成项目改造** | tuesday-js / YarnClassic | 有节点图基础 | 技术栈不符（原生 JS/React）；协议风险（GPL）；改造成本≈自建 | ❌ 不推荐 |
| **C. 框架自建 + 参考数据模型** | Vue Flow + Arcweave/Chat Mapper schema | 技术栈 100% 匹配；存量节点零迁移；定制自由度高；与 Pinia Store 天然联动 | 需自建属性面板；有一定开发量 | ✅ **推荐** |

### 最终选型：Vue Flow 自建

**框架**：`@vue-flow/core`（MIT，6.8k★，周下载 34 万，Vue 3 原生）

**选型理由**：
1. Vue 3 原生组件库，节点/边/连线全用 Vue 组件定义，与德塔 Pinia Store 天然响应式联动
2. MIT 协议，无传染风险
3. 周下载 34 万，持续维护（2026-07 仍发版），遇到问题社区资源丰富
4. 官方示例含 chatbot/对话树场景，choice 节点的多出口连线就是标准 edge 模型
5. 德塔剧情数据本身就是 JSON，Vue Flow 的 nodes/edges 模型与之天然映射

**德塔 6 种节点类型到 Vue Flow 的映射**：

| 德塔节点类型 | Vue Flow 实现方式 |
|---|---|
| dialogue（对话/旁白） | 单输入单输出节点，Vue 组件渲染说话人+台词预览 |
| choice（选项分支） | 单输入多输出节点，每个 choice 一个 Handle（输出端口），连线对应 next |
| condition（条件分支） | 单输入多输出节点，每条边带条件标签（好感度≥X 时走这条） |
| event（事件，自动跳转） | 单输入单输出节点，无 UI 交互，画布上标注触发效果 |
| input（玩家文本输入） | 单输入单输出节点，标注 placeholder 字段 |
| end（章节结束） | 单输入无输出节点，终止标记 |

**属性面板**：右侧栏，选中节点时 `v-model` 双向绑定节点属性（speaker/background/characters/effects 等），普通 Vue 表单组件即可。

**数据结构参考**：
- 节点 schema 参考 Arcweave JSON（elements+connections+branches+conditions+variables）
- 编辑器功能清单参考 Chat Mapper（角色节点/选项/分组/变量/条件/跨对话链接/自动布局/撤销/批量编辑）
- 最小实现参考 dialogbench（MIT，原生 JS+SVG，代码体量最小）

**架构参考**：visual-workflow-studio（Vue 3 + Vue Flow + TS + Pinia + Vite，技术栈 100% 同构，已实现分支节点+动态端口+JSON 导入导出+自动保存，仅做架构脚手架参考，无 LICENSE 不抄代码）

**运行时**：不换引擎。编辑器产出的 JSON 编译/转换为德塔现有 `{id, type, text, ...}` 节点格式，engine.js/visualNovelStore 不动，存量 474 节点零迁移风险。

### 不推荐直接集成的理由

- **GPL 协议风险**：Twine（GPL-3.0）代码集成会要求德塔开源
- **数据格式不匹配**：Twine（HTML）、Yarn（.yarn 脚本）、ink（.ink 脚本）、TyranoScript（.ks 标签）均非德塔 JS 节点对象，需写适配层
- **无成熟 npm 嵌入包**：@brink-lang/studio 极早期（1★），dialogue-forge 极早期（0★），不可靠
- **桌面应用不可嵌入**：inky（Electron）、Crochet（Tauri）、Monologue（Godot）、articy（Win/macOS）、TyranoBuilder（Steam）
- **商业 SaaS 依赖第三方**：Arcweave/Chat Mapper 需付费且内容生产依赖其平台，不符合自托管需求
- **停更项目**：Drawflow（2024-10 停更）、Litegraph.js（2024-08 停更）、YarnClassic（2024-12 停更）

## 六、对德塔项目的落地建议

### 实施路径

1. **安装 Vue Flow**：`npm install @vue-flow/core`（项目统一用 npm，不混 pnpm）
2. **新建「岁月史书」模块**：路由 `/chronicle`（或院长定名），TopBar 加入口
3. **编辑器页面**：Vue Flow 画布 + 右侧属性面板 + 左侧节点类型面板
4. **6 种自定义节点组件**：dialogue/choice/condition/event/input/end 各一个 Vue 组件
5. **JSON 导入导出**：编辑器产出 Vue Flow nodes/edges JSON，编译函数转换为德塔引擎节点格式（`{id, type, text, speaker, background, characters, next, choices, effects}`）
6. **存量兼容**：编写反向转换函数，把现有 prologue.js/chapter1.js 的节点数组导入编辑器画布（474 节点可视化）
7. **静态校验**：next 死链检测、id 重复检测、文案缺失检测（解决 BUG-58/BUG-59 家族的运行时才暴露问题）

### 分期建议

- **一期 PoC**：Vue Flow 画布 + dialogue/choice 两种节点 + 基本连线 + JSON 导出，验证「编辑器产出 -> 引擎消费」链路打通
- **二期**：补齐 6 种节点 + 属性面板 + 存量导入 + 静态校验
- **三期**：自动布局 + 撤销重做 + 多人协作（如果需要）

### 岁月史书模块后续

院长 2026-08-19 提出「岁月史书」除剧情编辑器外，还用于展示学院内数据（群聊统计/网站数据等），具体待后续规划。编辑器作为该模块的首个功能落地。
