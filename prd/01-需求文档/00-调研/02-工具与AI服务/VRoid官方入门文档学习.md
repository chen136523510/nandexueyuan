## 一、核心结论（先看这个）

1. **VRoid 官方定位**：零基础也能用的"人形 3D 虚拟形象"制作工具，思路是**预设拼装 + 滑杆微调**（选预设→调滑杆），不是自由建模——印证了「零基础全身 1-2 周」的可行性判断。
2. **建模五大部分**（官方原文划分）：Face（脸）/ Hairstyle（发型）/ Body（身体）/ Outfit（服装）/ Accessories（配件）——每个部分先从左侧图标栏选预设，再用右侧滑杆改形状/颜色/设计。
3. **文件双轨制（最重要）**：`.vroid` 是可编辑源文件（VRoid 专属格式）；`.vrm` 是导出的通用资产格式，**导出后不可再导入 VRoid 编辑**——资产管线单向，改模型必须回 `.vroid` 改完重新导出。
4. **无自动备份**：官方明确模型数据不自动备份，需手动备份 `.vroid` 到异地（硬盘其他位置/U 盘/云）。
5. **商用开放**：官方原文"创建的角色几乎可用于任何营利/非营利目的"（软件产出层面；内置素材授权细节见第七节待核实项）。
6. **VRoid Hub / VRoid Mobile 生态与我们无关**：官方推荐上传 VRoid Hub 分享社区——本项目为私有产品管线，**不上传**，本地导出 VRM 直接使用。

## 二、官方入门流程精读（Getting Started 原文整理）

### 2.1 软件定位

- 官方原话：为**没有任何 3D 建模/设计背景的初学者**开发；Windows / macOS / iPad 三平台。
- 创作方式：大量**预设物品（preset items）**挑选混搭成角色，且每个物品的形状/颜色/设计都可再调。

### 2.2 建模五大部分与编辑器布局

| 部分 | 官方操作描述 |
|------|-------------|
| **Face 脸** | 左侧图标栏最顶部图标 = 脸部预设列表；选中后中央角色即时变化；眉毛/鼻子/嘴等每个部件可单独调整 |
| **Hairstyle 发型** | 与脸同款交互（顶部图标 = 发型预设列表）；头发细分区块：**前发/后发之外还有 extensions（发饰延伸）、ahoge（呆毛）等** |
| **Body 身体** | 脖子以下全部；右侧滑杆调**身高、肩宽**等 |
| **Outfit 服装** | 按类别：上装/下装/连衣裙/鞋等；顶部图标 = 整套搭配预设，选完整套后**裤子/袜子/鞋可逐件替换** |
| **Accessories 配件** | 眼镜、毛耳等独立配件，官方称"给模型独特辨识度的最后一步" |

**编辑器通用交互**（官方原文归纳）：
- 左侧竖排图标栏 = 各部件入口，**每个标签页最顶部图标 = 该部分预设总列表**
- 右侧 = 当前所选部件的参数滑杆区
- 进阶：熟练后可编辑各部件的**贴图（texture）** 进一步提升（自定义贴图属于进阶功能）

### 2.3 官方学习路径建议

官方明确的基础流程顺序：脸 → 发型 → 身体 → 服装 → 配件，之后进阶玩贴图。与本项目《捏模操作指南》（会话内给出）的"左侧标签从上到下"顺序一致，已被官方文档印证。

## 三、文件格式与资产纪律（对项目最关键）

### 3.1 两种格式（官方原文）

| 格式 | 性质 | 可否再编辑 |
|------|------|-----------|
| `.vroid` | VRoid 专属工程格式，创建模型时即生成 | ✅ 可加载回 VRoid 编辑 |
| `.vrm` | 通用 3D 模型数据格式，用于导出/上传 VRoid Hub | ❌ **不可回 VRoid 编辑**；从 VRoid Hub 下载的 VRM 同样不能再编辑 |

### 3.2 单向管线的工程含义

```
.vroid（源文件，唯一可编辑形态）
   └─导出→ .vrm（成品资产，单向，不可逆）
```

- 任何修改（换表情/调色/改服装）都必须回到 `.vroid` 操作，再重新导出 VRM
- **与本项目「带背景原图必须留存」纪律同构**：`.vroid` = 源文件必须永久留存，`.vrm` = 抠图后成品
- 导出后想微调而源文件丢失 = 只能重做，无任何恢复手段

## 四、数据保存位置与备份（含本机实测）

### 4.1 官方路径（Windows）

| 数据 | 位置 | 可否自定义 |
|------|------|-----------|
| `.vroid` 模型数据 | 保存时可**自选任意位置**（模型选择界面"Open the folder location"可查看） | ✅ 可自选 |
| 自定义配件 custom_items | `C:\Users\<用户名>\AppData\LocalLow\pixiv\VRoid Studio\custom_items` | ❌ 固定不可改 |
| 自定义服装配件备份 | 导出为 `.vroidcustomitem` 文件，可自选保存位置 | ✅ 导出时可自选 |

### 4.2 本机实测验证（2026-09-25，黑机）

`C:\Users\13652\AppData\LocalLow\pixiv\VRoid Studio\` 实测存在，官方路径**准确**。子目录：`custom_items`（空，尚未创建自定义配件）、`edit_avatars`、`hair_presets`、`history_temp`、`preferences`、`Player.log`、`Unity`、`XWear`——后四个标签目录为文档未覆盖的实测发现（编辑头像/发型预设/临时历史/新衣装系统推测，未验证用途）。

### 4.3 备份与迁移（官方原文）

- **模型数据不会自动备份**；官方建议手动备份到 HDD 其他位置/U 盘/云服务
- 恢复：把备份文件放回保存目录即可继续编辑；**同名同目录会覆盖**，恢复时注意换名
- 换机迁移：新机须先启动一次 VRoid Studio 生成默认目录，再放入备份数据

## 五、VRoid Hub / VRoid Mobile 生态（本项目不采用）

官方推荐路线是上传 VRoid Hub 社区分享（收心/评论/SDK 游戏接入），配 VRoid Mobile 手机 AR 拍照。**本项目结论：跳过**——诺诺模型是私有产品资产，20 人朋友圈社区无公开分享需求；直接本地导出 VRM 进 three.js 管线。

## 六、对项目 3D PoC 的具体建议

1. **`.vroid` 源文件纪律（新增资产纪律建议）**：每次导出 VRM 的同时，`.vroid` 工程文件同步归档到统一资产目录（如 `E:\VRoid\projects\`），并按版本命名（`Nono-PoC-v1.vroid`），禁用"同名覆盖"。VRoid 恢复覆盖机制（4.3）意味着随手同名保存会静默吞版本。
2. **`.vrm` 不进 git**：VRM 二进制约 10MB+，与美工图片同理属黑机本地资产；入库 `public/` 的只能是处理后正式资产（PoC 阶段渲染页引用本地路径即可）。
3. **自定义配件即导即备**：若捏模用到自定义配饰（如诺诺的发饰），创建后立即导出 `.vroidcustomitem`——custom_items 目录不随模型走，丢失不可恢复。
4. **预设优先，微调其次**：官方流程本质是"选最接近的预设 → 滑杆精调"。PoC 阶段目标为验证管线而非定版形象，脸/发/服装各选接近预设微调即可，不追求逐滑杆打磨（定版轮再做）。
5. **贴图自定义后置**：官方将 texture 编辑列为进阶功能。诺诺服装上要是有项目元素（如男德学院徽记），进贴图环节再做，初版用纯色/默认纹样。
