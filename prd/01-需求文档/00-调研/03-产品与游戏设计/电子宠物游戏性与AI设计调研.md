# 电子宠物游戏性与 AI 设计调研

> 调研时间：2026-09-20
> 调研人：AI（白机，三路子 Agent 并行 + 主 Agent 交叉汇总）
> 背景：院长提出新需求——门户新页面养电子宠物（类腾讯 Q宠）：人物形象由黑机生成（动作表情丰富生动）、接入 AI（需设计上下文管理与记忆系统）、有摸头等基础互动、担心只有简单互动太单调、要求调研同类产品的游戏性设计。
> 用途：电子宠物新模块（拟登记 R-058）的 PRD 设计输入，重点回答三个问题：①玩法系统抄什么 ②AI 记忆怎么架构 ③"摸摸头"之外游戏性怎么加厚。
> 关联文档：本调研与 [测测产品调研与星河问扩建参考](./测测产品调研与星河问扩建参考.md) 同属"门户轻玩法"调研线；LLM 通道现状见 `.ai/handoff.md`（v3.8.0 DeepSeek 双通道）。

## 一、核心结论（先看这个）

1. **三产品的日活都不靠内容更新，靠"时间结构"**——衰减节律（Q宠 6 小时喂食/3 小时洗澡）、实时压力（拓麻歌子不管就死）、异步归来（旅行青蛙出门 3-4 天）分别把现实时间变成游戏资源。**网站形态建议衰减节律放宽到"按天"而非"按小时"**。
2. **2026-07 腾讯官宣 Q宠回归**（手机 QQ，3D 化），关键改动对我们极有参考价值：**接入混元大模型做性格预设+宠物日记**、**取消死亡机制（保留生病）**、社交强化（好友宠物互踩/投喂/PK/雇佣好友宠物打黑工）——大厂亲自验证了"AI 宠物 + 无死亡 + 轻社交"方向。
3. **情感人格化是留存核心，不是玩法**：TapTap 考古结论原话"QQ宠物成功的核心不是玩法（玩法单薄且苛刻），而是陪伴感与情感联结"。喂食洗澡只是道具，宠物会撒娇/打招呼/主动找你才是灵魂。
4. **LLM 记忆业界成熟方案是分层架构**（MemGPT/Letta 的核心记忆-情景记忆-归档记忆三层 + 男德通已有 chat_sessions/chat_turns 会话基建可复用），性格建模推荐"特质标签+自由文本人设"混合，不推荐 BIG5 参数化（对小项目过度设计）。
5. **游戏性加厚的性价比排序**（适合 20 人社区）：状态驱动行为 + 互动位置差异（纯前端成本低）> 每日日记/异步出行（AI 文案成本低）> 串门投喂轻社交（20 人熟人社区放大器）> 小游戏合集（开发成本高，后置）> 结婚生蛋传承（戏剧性最强，二期）。

## 二、经典电子宠物玩法考古（Q宠 / 拓麻歌子 / 旅行青蛙）

### 2.1 QQ宠物（2005-2018 原版 → 2026 回归版）

**基本盘**：2005-06-06 上线，2006-07 同时在线破百万，2018-09-15 停运（注册用户超 2 亿）。**2026-07-27 腾讯官宣回归**：手机 QQ 率先、3D 化、新增狗狗/蒜头鹅物种、保留喂食/洗澡/打工、**取消死亡机制、接入混元大模型做性格预设和宠物日记**。（来源：[中文维基](https://zh.wikipedia.org/wiki/QQ宠物)、[百度百科](https://baike.baidu.com/item/QQ宠物/204567)，多源一致）

#### 基础养成数值表（原版）

| 数值 | 机制 | 衰减 | 恢复 |
|---|---|---|---|
| 饥饿值 | 上限随等级增长（3000+等级×100 封顶 6000） | 各状态 -2~-8/分钟 | 喂食（50 元宝/900 点） |
| 清洁值 | 同上 | 同步衰减 | 洗澡（20 元宝/720 点） |
| 心情值 | 上限 1000 | 饥饿/清洁告急时 -15/分钟以上 | 点击身体部位 +5~70/次、喂食/洗澡 +20、玩具 +100/分、小游戏 +50/分 |
| 成长值 | 决定等级，不衰减 | — | 心情 900+ 时 260 点/小时（30% 加成） |
| 健康 | 状态而非数值 | 饥饿/肮脏诱发疾病 | 看病开药 |

体感节奏（知乎考古）："**在线 6 小时就得喂一次饭，3 小时得洗一次澡**"。等级解锁：4 级打工 / 5 级旅游 / 6 级上学 / 15 级结婚。宠物饿/脏时会在桌面主动做动作提示（挠痒、叫）。（精确数值仅百科单源，方向经多源印证，设计时仅作量级参考）

#### 经济系统

- 元宝（Q币兑换/活动获取），新领养送 300 元宝 + 1 颗还魂丹
- **打工 8 小时制**：工资按等级+学历分配；**学习奖学金**：小学 20 / 中学 50 / 大学 100 元宝每门课
- 核心消耗：食物、日用品、看病 50 元宝、**还魂丹 400 元宝**
- **残酷循环（设计精髓）**："宠物越饿越脏，越需要打工养活自己，越打工就会越饿越脏"——被玩家称为"打工人模拟器"（TapTap 考古文+搜狐转载互证）

#### 社交玩法

- **串门/旅游**（5 级解锁）：拜访好友/逛好友圈（一次最多 3 家），回家汇报见闻、可能带回小客人，点亮地图区域领奖励
- **宠物炫**：学校学动画技能，派宠物去好友桌面表演
- **结婚**（15 级）：教堂买戒指求婚，每天限 1 次求婚；爱情值=戒指初始值+成长增长
- **生蛋**：婚后 200 小时可培育，**每只宠物一生仅 10 次生蛋机会**——刻意稀缺
- **2026 回归版社交强化**：好友宠物互踩续火花、投喂、PK、战力值、**雇佣好友宠物打黑工**（不每 30 分钟召回，赚的钱全归好友——制造半小时间隔回访钩子）

#### 生死机制（原版 vs 回归版）

- 原版：生病（药不对症越吃越重）→ 死亡二选一：复活（还魂丹，保留成长）或埋葬（清档重养）。大量"童年伤痛"玩家叙事
- **2026 回归版：取消死亡，保留生病**——官方亲自修正了"死亡创伤"设计

#### 留存设计拆解

双循环嵌套：**生存循环**（在线→衰减→喂食洗澡→烧元宝→打工→打工加速衰减）+ **成长循环**（心情→成长→等级→解锁打工/上学/旅游/结婚）。前者制造"必须回来"，后者制造"想快点回来"。情感人格化（上下线打招呼、挂机俏皮动作、土味情话）是核心。

### 2.2 拓麻歌子（1996 至今，总销量 9810 万台）

**核心三计量表**：饥饿/开心/纪律，另监控年龄体重。特色机制：

- **数值互锁**：小游戏提升开心度+赚钱，但消耗体重与饱腹感；零食无限但增重致病
- **行为训练**：宠物排便前有预兆，引导如厕多次成功即"学会上厕所"——**宠物学会技能**的早期形态
- **训斥机制**：宠物不需要却撒娇呼叫注意力时，训斥提升纪律值——惩罚不当撒娇
- **进化分支即成绩单**：成年形态由此前各阶段照顾质量决定，照顾得好得到"更聪明、需要更少照料"的形态——**形态可社交展示**
- **世代传承**（对社区最有参考价值）：联机培养感情→结婚→**女方产两颗蛋双方各留一颗**→父母引导宝宝 24 小时后离开→玩家养育下一代无限延续——"养的是家族史不是一只宠物"；后期机型叠加基因混合遗传（m!x/On 世代）

（来源：[英文维基 Tamagotchi](https://en.wikipedia.org/wiki/Tamagotchi)，中文维基部分印证）

### 2.3 旅行青蛙（2017-2018 现象级）

4 人团队 10 个月开发，中国区下载占全球 95%。设计哲学（制作人上村真裕子两篇一手访谈，[新华网](https://baijiahao.baidu.com/s?id=1590878818182712032)、[读特新闻](https://www.dutenews.com/n/article/116412)）：

- **反竞争**：明确希望玩家不竞争不攀比，按自己节奏悠闲游玩
- **"放置玩家"而非放置游戏**：青蛙出去玩，玩家看家；主动权在青蛙
- **青蛙不成长**：刻意砍掉等级成长轴，只剩牵挂轴
- **信息不透明即玩法**：行李影响际遇但不告知结果，"大家认真思考后得到的那个结果，才是问题的答案"——攻略会杀死想象层
- **牵挂感**（原话）："**想要去照料却无法照料的部分，会更让人焦急在意**"
- 三叶草经济：3 小时长满上限 20 片，宽松闭环"够用但不富裕"；明信片取材真实名胜，天然适合 SNS 晒图传播
- ⚠️ 最新动态：IP 授权到期，**2026-12-08 中国区停服**（借势怀旧窗口仍在）

### 2.4 共性规律：什么样的机制让人留存

| 机制 | 三产品验证 | 底层心理 |
|---|---|---|
| 真实时间异步变化 | Q宠按小时衰减 / 拓麻实时 / 蛙出门 3-4 天 | 世界不因下线而停止 → 回访理由 |
| 生存压力/牵挂 | 死亡 vs 不知何时归 | 同一情感杠杆两种实现：恐惧失去 vs 期待归来 |
| 操作边界克制 | 3 键 / 几乎零操作 | 越不能完全控制，越投入想象 |
| 经济劳动闭环 | 打工/小游戏/割草 | 付出换来的才被珍惜 |
| 成长/收集沉淀 | 等级 / 进化形态 / 明信片图鉴 | 成绩单可展示 |
| 社交绑定 | QQ 关系链 / 联机传代 / 晒明信片 | 宠物成为社交货币 |
| **人格化情感** | 打招呼/撒娇/俏皮动作 | **陪伴感是核心（不是玩法）** |
| 稀缺仪式 | 10 次生蛋 / 四叶草 | 限量制造珍贵感 |

## 三、AI 宠物记忆与性格设计

### 3.1 AI 宠物产品案例

| 产品 | 记忆/性格设计要点 | 启示 |
|---|---|---|
| **Moflin**（日本，CES 2021 创新奖） | **无 LLM 的情绪引擎**：二维情绪表达图谱（可理解为"效价×唤醒度"平面），情绪随互动在图谱上移动；**性格不是预设而是日常互动情绪累积的涌现结果**，最终呈现 happy/easy going/stressed 等不同倾向，每只个体性格不同 | 性格=情绪长期累积的涌现，二维情绪图是零成本高表现力的情绪建模方案 |
| **Ropet**（CES 2025，$299） | LLM 硬件宠物（ChatGPT/Gemini 驱动对话，大部分功能本地处理）；面部识别认主+LONG-TERM MEMORY；性格"learn and adapt to your personality"（温柔/古怪/外向方向由互动统计塑造）；39°C 恒温体温+LCD 眼睛渲染情绪；互动赚积分换配件 | "Daily interactions shape its personality"；躯体细节（体温/眼神）对情感的作用 |
| **Talking Tom 家族**（Outfit7，180 亿次下载） | 语音模仿+肢体交互（tickle/poke/play）；**My Talking Tom 2 四状态条：hunger/hygiene/energy/bladder**，随时间衰减需持续照料；角色级静态性格标签（wisecracking/grumpy/mischievous），性格不演变 | 四状态条是衰减驱动回访的经典实现；静态性格标签靠差异区分产品线 |
| **猫箱**（字节跳动，豆包底座） | 角色记住用户偏好，**情感积累到一定程度主动发起对话**；回复带括号表情动作描写 | "主动搭话"是 AI 宠物区别于工具的核心行为 |
| **iPET**（ACL 2025 Demo 学术系统） | LLM 虚拟宠物 agent 三模块：对话 + **记忆模块（存储并综合用户与宠物双侧经历）** + 世界模拟（高层反思引导下生成偏好驱动的行为）；非商业部署 200 天百万级用户 | 学术验证了"双侧经历记忆+反思驱动行为"架构可行 |

### 3.2 LLM 记忆系统架构对比

**① MemGPT / Letta——"操作系统式"分层记忆（学术源头）**（论文 arXiv:2310.08560，UC Berkeley；现行产品 docs.letta.com）：
- 借鉴 OS 分层内存：**Main context**（prompt 内）= 系统指令（只读内核）+ **working context**（固定大小读写块，存自我认知与用户关键信息）+ FIFO 消息队列（队首递归摘要）；**External context**（prompt 外）= recall storage（全消息库，语义查询）+ archival storage（知识库，向量检索）
- **记忆水位机制**：token 达 70% 注入警告，让 LLM **自己把重要信息存入记忆（self-editing memory）**；达 100% 驱逐最旧消息并生成递归摘要
- Letta 产品化形态：**Memory blocks**（label/value/limit 结构，persona block + human block 两个标准块，XML 注入 system prompt）+ archival memory（向量库，`archival_memory_insert/search`，agent 自主决定存什么）

**② mem0——生产级"记忆中间件"**（GitHub mem0ai/mem0）：
- 2026-04 v3 算法：**单遍 ADD-only 提取**（一次 LLM 调用，只积累不覆盖）+ 实体链接 + 多信号检索融合（向量+BM25+实体匹配）+ 时间感知
- 三级作用域 User/Session/Agent；API 极简（add/search）；LoCoMo 71.4→92.5

**③ Generative Agents（斯坦福小镇）——记忆流三因子**（arXiv:2304.03442）：
- Memory Stream 平铺存储所有观察（自然语言+创建时间戳+最近访问时间戳）
- **检索三因子加权**：`score = recency（0.995^小时指数衰减）+ importance（LLM 创建时打 1-10 分）+ relevance（embedding 相似度）`
- **Reflection 反思机制**：最新事件重要性总和超 150 触发（约每天 2-3 次）→ 取最近 100 条 → LLM 生成高层问题 → 检索相关记忆 → 提取 insights 存回流中，形成**反思树**——agent 会依据共享兴趣（而非互动频率）选择社交对象

**④ 角色对话产品的用户可见记忆（产品界实践）**：
- **Character.ai 三代演进**：Pinned Memories（长按 Pin 固定）→ Chat Memories（手写 400 字符）→ **Facts（自动提取人物属性，按"你的 Persona/当前角色/配角"分类展示，可编辑/停用/删除）+ Story Memory（用户 Pin 固化，protected 不被自动清理）**；新会话显式提示"copy Facts"；Memory Usage 占用条可视化
- **星野（MiniMax）**：**事件簿**——聊到一定轮次自动生成阶段性摘要固化关键记忆；六大进程控制（重说/回溯/记忆/重启/**评价打分（让角色逼近用户偏好）**/事件簿）；**星念**——AI 生成唯一性纪念卡（正面图像+背面故事线）
- **筑梦岛（阅文）**：记忆即"梦境"——聊天记录保存为梦境，下次接续上次话题；热点话题一键加入记忆

### 3.3 业界共识：三层记忆架构

所有方案收敛为同一结构：

```
L1 常驻核心记忆（每次必注入 prompt）—— persona + 用户画像，小容量（Character.ai Facts / Letta memory blocks）
L2 短期上下文窗口（原文滚动）————— 最近 N 轮对话原文 + 更早内容的滚动摘要（MemGPT FIFO / 星野事件簿）
L3 长期记忆库（按需检索注入）————— 事件/事实存储 + 检索（向量/关键词/时间加权，mem0 / Generative Agents）
        + 记忆固化管线：会话结束或水位触发 → LLM 提炼重要事件 → 去重入库
```

### 3.4 性格系统建模方案对比

| 方案 | 代表 | 优点 | 缺点 |
|---|---|---|---|
| A. BIG5 数值参数化 | 学术验证（可让 LLM 稳定输出特定人格） | 可量化 | **无产品背书**；数值对 LLM 行为控制不如自然语言精确；过度设计 |
| B. 特质标签表 | Replika（Playful/Logical 等 traits，社区经验 **3 个左右效果最佳，多了混乱**）；Talking Tom 家族 | 用户可见可理解、可游戏化 | 表达力上限低 |
| C. 自由文本人设 | **SillyTavern 角色卡**（角色扮演社区事实标准：Description 全量自由文本 + Personality 简短摘要 + Scenario + **First Message 定风格基线**）；Character.ai | 表达力最强、LLM 理解最好 | 占 token（1000-token 人设会把可用记忆砍一半） |
| C+ 世界书/Lorebook | SillyTavern World Info：**关键词触发的动态设定注入**，支持扫描深度/递归触发/token 预算/概率触发（1% 唤醒古神） | 大设定按需注入不占常驻 token | 关键词命中有漏报 |
| D. 性格随互动成长 | Moflin（情绪涌现）、Ropet（互动塑造）、星野（评价打分逼近偏好） | 情感黏性最强，"独一无二"叙事 | 需防漂移机制 |

**结论：产品界主流是 B+C 混合（自由文本人设打底 + 少量可见特质标签做游戏化钩子）+ D 做长线情感留存**。

## 四、桌宠形态与互动深度设计（VPet / Shimeji / Bongo Cat / Neopets）

### 4.1 VPet——功能最全的养成型桌宠基准（免费开源，Steam 好评如潮 95%）

**动画体系**（一手：仓库源码目录 `mod/0000_core/pet/vup/`，官方称 32 种类×4 状态×3 类型 = 200+ 动画）：
- 互动类：`Touch_Head`（摸头）/`Touch_Body`（摸身体）/`Pinch`（捏）/`Raise`（提起）——**触摸分区各有独立动画类**
- 日常类：IDEL/MOVE/Sleep/Eat/Drink/Say/Think/Music/Gift
- 情境类：`BDay`（生日）/`LevelUP`/`StartUP`/`Shutdown`（开关机问候）/`SideHide_Left/Right`（贴屏幕边探头）
- 工作类 13 种：书法/烤肠/跳绳/学习/学画/打工/清洁……**每个工作目录下再分 Happy/A/B 状态差分**（同一工作在开心/不佳状态下动画不同）

**数值系统**（一手：`GameSave_VPet.cs` 源码）：九维属性（钱/经验/等级/好感/体力/饱食/口渴/心情/健康），好感升级上限+10；**生病判定公式：心情≥80% 减 12、好感≥80 再减 12——照顾质量实际反哺健康**。

**食物系统**（一手：`food.lps` 数据文件）：每条食物 12 字段，含 `graph` 字段**绑定专属吃/喝动画**；**数值有正有负**（可乐 Health -1 但 Feeling +50）——食物是权衡不是单纯奖励；desc 全是梗文案（"雷碧——透心扬，心飞凉"）；食物/药品/礼物（加好感）/限时食品分库管理。

**台词条件触发系统**（一手：`ICheckText.cs`/`ClickText.cs`，本项目最值得抄的设计）：台词不是随机播报，而是**每条声明自己的触发条件**——状态四态 Flags（Happy/Nomal/PoorCondition/Ill）× 时段四段（Morning/Afternoon/Night/Midnight）× 好感区间（LikeMin/LikeMax）× 健康区间 × 工作情境（睡觉时不说错话、可指定只在干某活时说）。

### 4.2 Shimeji——纯行为驱动桌宠的教科书

**双文件行为架构**（一手：官方 `actions.xml` + `behaviors.xml`）：动作（最小动画单元+位移）与调度（何时执行）分离，默认动作 100+：移动（走/跑/爬行/趴）、坐姿细分（垂腿坐/转头/**盯着鼠标看**/面向鼠标）、攀爬（墙/天花板）、摔落（Fall/**Tripping 走路绊倒自己**）、窗口互动（**ThrowIe 把浏览器窗口扔出去**/扛着窗口跑/坐窗沿）、用户互动（追鼠标/被拖拽/**被拖时挣扎 Resisting**）、多宠彩蛋（一分为二/把同伴从窗口边拉上来）。

**调度三件套**：①`Frequency` 权重（权重比=概率比，设 0 关闭）；②`Condition` 环境表达式（在地上吗/朝向/分裂数量<50/在窗口边上吗——宠物"知道自己在哪"）；③`NextBehavior` 转移链——行为结束按子权重抽下一个，**马尔可夫链式随机接续，同一行为永不固定收尾**。

### 4.3 Bongo Cat——极简互动+收集循环的爆火样本

Steam 版核心循环官方原文："Every time you press a key, Bongo cat will punch your taskbar"——**把用户本来就在做的事（打字）变成宠物行为的输入，互动零成本**；积分开箱掉帽子，掉落池公开（Common 90% / Rare 0.49% / **Legendary 1/500000**——公开的极小概率本身是传播话题）。96% 好评 2.9 万评测；标签暴露本质：Desktop Companion / **Idler / Typing / Incremental**。开源版 23.4k stars。

### 4.4 Neopets——26 年网页宠物社区的留存答案

1999 年上线至今，2005 年峰值 3500 万用户/月浏览 40 亿。**留存三支柱**：①小游戏经济闭环（赚 Neopoints → 银行/炒股/开商店/拍卖 → 变宠物外观，货币有"用处的深度"）；②**养成不惩罚**（宠物被忽视不会死，但健康影响玩法）；③社区 UGC（公会/论坛/用户投稿周报/可解锁头像本身就是收集品）。**宠物的宠物（Petpets）——收集层级嵌套**。技术教训：Moshi Monsters 死于 Flash 依赖，Neopets 靠 Ruffle 模拟器续命——**Web 宠物动画要用 Canvas/DOM/CSS，勿依赖会淘汰的运行时**。

### 5.2 推荐架构：三层记忆 + 二维情绪 + 条件台词（性价比最高的组合）

```
【AI 层】（复用 llm.js，成本≈普通对话 ×1.2）
  L1 常驻核心记忆：pet_memory（宠物自我认知：名字/性格/近期状态）+ user_memory（宠物眼中的主人）
      —— 各限 1000-2000 字符，用户可见可编辑（Character.ai Facts 翻版，"它记得我说过的话"是 20 人社区最强传播点）
  L2 短期上下文：最近 20-30 轮原文 + 滚动摘要（一条 session_summary 字段）
  L3 长期记忆库：memory_events 表（时间戳+内容+类型+重要度分 1-10）
      检索：关键词 LIKE + 时间衰减 0.995^天 + 重要度加权（Generative Agents 三因子的纯 SQL 实现，20 人规模无需向量库）
  记忆固化：每会话结束跑一次单遍 LLM 提取（mem0 式 ADD-only），几百 token/次

【性格层】
  基础 = 自由文本人设 300-500 字（SillyTavern 模式，First Message 精心写——风格锚点）
  可见特质标签 3-5 个（傲娇/贪吃/记仇/黏人——Replika 经验 3 个最佳，部分随互动解锁）
  情绪 = Moflin 二维情绪图：效价（开心↔低落）×唤醒（平静↔激动）两个 float 存 DB，
         互动事件驱动移动+时间回归基线；当前情绪一句话注入 prompt 影响语气（零 LLM 成本）
  成长 = 羁绊等级 1-10（互动天数/轮次/事件驱动），升级触发"阶段反思"（LLM 总结关系现状写入 L1，
         同时重申性格基线——天然防漂移，即星野事件簿+Generative Agents 反思合体）

【表现层】（黑机出图，复用视觉小说差分管线）
  动画组织照抄 VPet：触摸分区（摸头/摸身/戳脸/捏脸）× 心情四态（开心/普通/无聊/生病）差分
  台词条件化照抄 VPet ICheckText：每条台词声明（状态×时段×好感区间），社区内部梗填库
  行为随机接续照抄 Shimeji NextBehavior：互动结束权重随机播报反应，永不固定收尾
```

### 5.3 数值与留存设计（按天节律，勿抄 Q宠按小时）

- **数值砍到 4-5 维**：心情/饱食/好感/金币（VPet 九维太多，Talking Tom 四条刚好）——**衰减按天不按小时**（网站形态用户不是常驻在线，Q宠 6 小时喂食节律是 PC 挂机时代产物，2026 回归版也放宽了）
- **生病但不死**（2026 版 Q宠官方结论，直接抄）：疏于照顾会生病要花钱看病，砍掉死亡创伤
- **主动气泡**：饿了/无聊提示、时段问候、社区事件播报（"XX 今天也来看我了"——猫箱式主动搭话）
- **互动掉落收集**：摸头/喂食/签到按五档概率掉"表情差分卡/服装/称号"，**公开图鉴+公开概率**（Bongo Cat 验证公开的极小概率本身是话题）；掉落物优先复用表情差分资产

### 5.5.1 Live2D 路线三轮核实（2026-09-23 白机，两路子 Agent 并行联网核实）

院长提出针对 Live2D 形式专题讨论，本节为定向补核。**四条关键事实推翻/修正了上表的成本与运行时认知**：

**① C 档运行时选型修正：pixi-live2d-display 已停更，改荐官方 SDK 直渲**
- guansss/pixi-live2d-display：最后 master 提交 2023-12-15，最新版仍停留在 v0.5.0-beta（2023-12-07），**不支持 PixiJS v8**（issue #135/#166 open），应视为停止维护
- 替代路线健康：**官方 CubismWebFramework/ CubismWebSamples（TS，MIT 系许可）R5 于 2026-04-02 发布**，WebGL2 直渲零 PIXI 依赖，官方每年 1-2 版稳定维护，兼容 Editor 5.3；社区侧 `untitled-pixi-live2d-engine`（PixiJS v8 + Cubism 2~5 全支持，2026-09-20 仍在更新）、WebGAL 官方维护的 fork（2026-07 push）、`live2d-widget`（11k star，2026-09 仍更新）均活跃
- 结论：**web 渲染不是阻塞项**，C 档若启动用官方 SDK 直渲，勿再引用 pixi-live2d-display 原库

**② 模型获取成本大幅下修：C 档从"三期旗舰"变为"可低成本试水"**
- 上表 C 档成本"40-80h 自建 / 外包 2000-8000 元"是 VTuber 精模行情；**Q 版/简单角色外包实际报价：250~980 元/只**（国内画师接单渠道，二手摘要级，平台：米画师/B站工房/触站）；rigging-only（客户供分层立绘）2000-2500 元起
- **BOOTH 现成模型 500~4,500 日元（约 25-225 元）共 1.6 万件**，但无平台级商用条款，须逐商品读卖家 Terms（通常禁再配布模型本体，能否嵌入 App/游戏因品而异）
- **官方免费模型 32 个**（Hiyori/Haru/Shizuku 等，Free Material License v1.6）：年销售 <1000 万日元者**可商用可修改可分发**，需署名 "This content uses sample data owned and copyrighted by Live2D Inc."；**Hiyori/Miara 禁止设计改动**（与"毛色差异"待裁决项冲突，若用官方模型则毛色定制不可行）
- **AI 自动建模 2026-09 不存在**：无任何可商用的"立绘→Live2D"服务，仅有论文阶段研究（Bunraku arXiv:2607.27348 / See-through / CartoonAlive）；人工建模（数周）或外包仍是真实成本
- Editor FREE 版限制（参数≤30/ArtMesh≤100/变形器≤50/纹理 1 张 2048px）**对 Q 版简单模型够用**——自建也不用买 PRO（PRO for indie 约 750 元/年订阅）

**③ 模型体积与交互 API 全利好**：官方标准全身模型（Haru）moc3 376KB + 贴图 1.46MB ≈ **2MB/只**，20 人社区零压力；程序化触发是标准能力——motion 播放、**hit 命中区域点击事件（摸头交互直接支持）**、参数级控制、自动眨眼/口型内置

**④ B 档（Spine 类）维持跳过，证据更硬**：Spine 网格变形需 Pro（$379）且 `spine-pixi` npm 停在 4.1（4.3 未发包）；DragonBones 编辑器冻结在 5.x；LoongBones 仅 2 star 3 commits 基本停滞；WebGAL 曾因 Spine 运行时许可摩擦移除 pixi-spine（每个用户理论上需自持 license 的条款）

**伪 Live2D（A 档）定位补强**：E-mote（M2 商业产品）即"部件层变形动画"路线的成熟形态，采用作品含猫娘乐园/爱上火车等——A 档效果上限有十余年商业化背书；但**无现成 DOM/CSS 伪 Live2D 开源库**，A 档是自研缩水版 E-mote，2-4h/只估价逻辑成立

**修订结论**：C 档解锁"零成本 PoC 路径"——用官方免费模型（如 Haru）+ 官方 SDK 在 Vue3 内跑通渲染/hit/motion 管线约半天工作量，形象路线可先验证体验再决定是否为专属形象花 250-980 元外包 Q 版。A 档一期起步的原推荐不变（形象自主权在黑机 Seedream 管线），C 档从"三期旗舰"下修为"二期可试水选项"。遗留适配疑点：外包建模师是否接受 Seedream AI 立绘拆层 PSD（Live2D 建模对分层完整度有要求，未调研，走 C 档前须先确认）

### 5.5.2 建模可行性四轮核实（2026-09-23 白机；院长裁决"零外包/AI 辅助/全身建模/可行性第一"后两路深挖）

> 院长当轮另裁决：①全部工作自研，禁止外包 ②相信 GPT6 时代 AI 辅助建模已可行 ③要求免费建模工具 ④全身建模+真实场景 ⑤**建模可行性为最高优先级** ⑥核心设计理念=诺诺是 LLM 大脑自主调用程序执行动作的独立个体（后置处理）。产品形态已从"每人养一只"质变为"全站共享诺诺虚拟直播间（弹幕互动/30 分钟无活动则打瞌睡或看书/场景椅子可坐）"。

**核心结论：全身建模技术上能实现，但"免费工具 + AI 辅助轻松完成"的预期不成立——卡点是硬数字与手工技艺。**

**事实 1：Cubism FREE 版数字上做不了全身美少女（一手数据双源证实）**
- 官方标准参数集共 **40 个**（27 核心+13 可选，官方手册），本身已超 FREE 的 30 参数上限
- 官方示例模型二进制实测（CubismWebSamples + moc3 格式解析）：

| 官方模型 | 形态 | 参数 | ArtMesh | 变形器 | 纹理 |
|---|---|---|---|---|---|
| Mao | 全身魔法少女 | 132 | 262 | 178 | - |
| Ren | 全身和风少女 | 73 | 198 | 150 | - |
| Rice | 全身吉祥物 | 96 | 178 | 138 | - |
| Hiyori | 半身教材 | 70 | 134 | 104 | **2 张 2048** |
| 能塞进 FREE 的 | 仅简笔小人/小狗级 | 21-25 | 30-34 | 28-34 | - |

- FREE 上限（30 参数/100 ArtMesh/50 变形器/30 部件/1 张 2048）对全身模型全面超限 2-5 倍；日本 Live2D 制作公司 BB Enterprise 用 FREE 实测只做到半身，原话"さすがに体までは無理でした"（做到身体是不可能的）

**事实 2：AI 辅助边界——拆层可交给 AI，绑定不能**
- **See-through**（正确编号 arXiv:2602.03749；代码 github.com/shitagaki-lab/see-through，4.1k star，Apache-2，2026-04 仍活跃）：单图自动分层+遮挡补全，黑机 4070 12GB 可跑（12GB 需 offload/8GB 有量化方案），另有 HF/ModelScope 在线 demo；社区实测"省约一整天，需后处理（左右臂分离/漏检饰品）"；作者明示**不含 rigging**
- **绑定环节（网格布线/变形器嵌套/参数/物理/动作曲线）AI 辅助为零**：.moc3/.cmo3 闭源无 API；2026-09-21 r/ClaudeAI 一手帖（问"谁真用 AI 做成过 Live2D"）**无任何成功案例**，专业从业者证词"AI 做不了这种复杂建模绑定，短期也做不到"（疑训练数据不足）
- GPT-6（GPT-6 Astra，2026-09-04 发布）computer use 主打能力可驱动 Blender/KiCad 等专业软件（OSWorld 72.6%），但**无操作 Cubism 完成建模的公开案例**
- Bunraku（arXiv:2607.27348，单图→可编辑 Live2D）代码为空壳仓库不可用；新自动 rig 项目 psd2live（2026-09-03 创建/443 star，半身）、image2live2d（声称全身/35 star）仅数周龄，输出质量未验证

**事实 3：零基础真实周期（多样本）**
- 入门首个半身模型：1-4 周
- 全身（不含精细走路）自用/演示质量：**2-4 个月，100-200 小时**（有经验者第二个全身模型仍需 41.5h）
- 全身+走路+坐姿可展示质量：**4-8 个月，200-400+ 小时**——走路循环在 2D 伪 3D 网格变形框架内透视极难，社区无成功先例、官方无教程（"全身适合 3D"是社区共识）

**事实 4：合规获取 PRO 能力的路径**
- **42 天 PRO 试用**（官方）：到期降级 FREE 不锁死；期间导出的 .moc3 永久有效、无水印证据；但超限工程到期后无法再保存修改（改模型受限，motion3 可独立编辑的程度未验证）
- PRO for indie 订阅：首年 14,280 日元（约 700 元人民币，营收<1000 万日元档）
- nijigenerate v1.0-beta（开源无限制，Inochi 事实续作，2026-08 活跃）：纯免费但无稳定版，**web 运行时开发中**，不支撑当前 web 直播间形态

**事实 5（利好）：坐姿与"LLM 自主调用动作"路径成立**
- Live2D 坐姿/走路=预制 motion3 关键帧动画（非实时 IK）：Editor 做好姿态 → 运行时按指令播放（Unity 侧 Collider+状态机方案成熟；Web 侧 Framework motion API 等价）
- 与院长第 6 点理念天然兼容：**LLM 决策"我要坐下/去看书"→ 工具调用播放对应 motion → 坐姿/看书待机**，动作库即 Agent 的工具集；椅子=场景美术与坐姿机位对齐，满足"能坐不是贴图"

**可行性裁决建议**：先用 1-2 周做**半身诺诺 PoC**（Seedream 出图→See-through 拆层→Cubism FREE 绑定→官方 Web SDK 渲染+动作触发），以真实体验验证学习曲线与 AI 辅助效率；通过后再开 42 天 PRO 窗口集中做全身（或订阅 PRO）。走路循环列为单独技术攻关点，若 Live2D 走不通，机位/场景调度（镜头跟随+局部动作）是备选叙事手法

### 5.5.3 3D 路线五轮核实（2026-09-23 白机；院长问"如果是 3D 呢"后两路深挖）

**核心结论：3D 路线在"免费+零外包+AI 辅助+全身+真实场景"四个约束下全面优于 Live2D，制作端最大卡点从"技能墙（数月）"降为"审美精修（数天~两周）"；Web 渲染可行性 A-（高）。**

**① 制作工具：VRoid Studio 全免费（pixiv，当前 v2.14，2026-06 月更中）**
- 个人/企业均可**免版税商用**自制模型，导出 .vrm；限制仅"不得做竞品 avatar 服务/不暗示官方背书"
- 零基础耗时（B站多教程实测）：分钟级出雏形，精修 3+ 小时/模型，**1-2 周达可直播质量**（对照 Live2D 全身 2-4 个月）
- **VRM 开箱即用**：humanoid 骨骼 + 18 个标准表情 blendshape + 眨眼（lookAt/blink）+ 口型五音素（aa/ih/ou/ee/oh）+ spring bone 头发裙子物理——Live2D 里的"绑定地狱"在 3D 不存在
- 硬件门槛极低（i5+8G+核显），4070 过剩

**② 现成动画消灭走路/坐姿卡点（3D 对 2D 的碾压点）**
- **Adobe Mixamo 仍免费**（2026-09 页面在线，免费 Adobe ID）：千级专业动捕全身动画（走路/idle/坐姿/手势）+ 上传模型自动绑骨；单个动画重定向到 VRM 熟练后分钟级（教程 7-8 分钟讲完全流程）
- AccuRIG 2.0（Reallusion，免费）：自动绑骨 + 4500+ 动作，官方有"AI 生成模型绑骨"专篇教程
- Unity 侧 UniVRM 导入即 Humanoid，原生支持重定向；坐椅子=坐姿动画+场景道具对位的常规工程
- 对照：Live2D 走路循环 4-8 个月无先例；3D 走路半小时级

**③ AI 图生 3D：辅助成立、全自动不成立**
- 免费额度充足：Tripo 200 积分/月（免费版**非商用**）、Meshy 100 积分/月（**CC BY 需署名**）、腾讯混元 3D 国际版 **20 次/天**（基于混元 3D 2.5，自动绑骨/动画）
- 已有公开实战：r/ChatGPT（2026-09-06）"GPT-6 + Blender + Tripo 分件生成，一天出可跳舞角色，半天且大部分无人值守"，但作者自述"仍需 3D 知识纠错"；复现者在**动画环节全灭**（AI 全自动到动作衔接不可靠）
- 通病：背面崩坏/头发怪 mesh/手指不可靠/大眼比例失真；**不直接输出 VRM**（经 Blender VRM Add-on 免费转换）；本地开源仅混元 3D-2 形状生成（6GB）4070 可跑，TRELLIS 需 16GB 不达标
- 正确用法：道具/小物件 + 角色原型迭代 + GPT-6 辅助 Blender 修模（GPT-6 官方演示即操作 Blender，2026-09 有 60 万播放实测）；不指望端到端成片角色

**④ Web 渲染：three.js r186 + @pixiv/three-vrm 3.5.5 + Colyseus，评级 A-**（详见专题文档 `00-调研/01-技术/诺诺虚拟直播间Web3D渲染可行性调研.md`）
- three-vrm 加载 VRM 约 10 行代码、表情/口型单行 API、支持 vrma 动画重定向；模型 5-20MB（可优化到 5MB 内），20 人首载可接受
- **20 个观看者=20 个浏览器本地 GPU 渲染，服务器零渲染负载**；WebGL2 支持率 96%
- 扣分项（需 PoC 实测）：低配手机帧率无公开基准；弹幕→LLM→TTS→动作端到端时延无公开数据
- 审美上限：MToon 卡通材质=VRChat/VRoid 级干净卡通（约原神观感 6-7 成）；原神级需 Unity+定制管线+手工资产（社区 700★ 复刻均困在 Unity 内），20 人社区不建议追

**⑤ 关键先例：Neuro-sama 已验证"AI 主播+3D"路径**——原为 Live2D（Hiyori 免费模型），2025-11 起换 3D 模型（运行于 Unity）仍居头部（Twitch ~101 万粉）；即"先 2D 后 3D"和"直接 3D"都有先例。开源参照 Amica（1598★，浏览器 VRM+LLM 对话）、TalkingHead（1565★）

**⑥ Unity 桌面端的三个矛盾全部有解**（回应院长第 5 点）：客户端照连 Colyseus（Unity SDK 官方一等支持）共享同一只诺诺 / 状态服务器权威同步 / API key 永不内置、所有调用走 Express 代理。桌面端真正代价只是分发摩擦（20 人装客户端+自动更新），失去"点链接即看"

**路线对比与建议**：

| 维度 | Live2D | 3D VRoid |
|---|---|---|
| 全身模型 | 2-4 个月 | 1-2 周 |
| 绑定/表情/口型 | 手工，AI 零辅助 | VRM 内置 |
| 走路/坐椅子 | 4-8 个月无先例/基本无解 | 现成动捕动画，分钟~小时级 |
| 3D 房间活动 | 不支持 | 原生支持 |
| 软件成本 | PRO 约 700 元/年或 42 天窗口 | 全免 |
| 最大风险 | 周期与技能墙 | "VRoid 脸"辨识度/审美精修（与院长图像功底匹配） |

**修订建议**：形象路线由 Live2D 转向 **3D VRoid 主干**；PoC 改为 3D 向——Seedream 出诺诺设定图 → VRoid 捏模（1-3 天）→ VRM 进 three.js 网页渲染+表情/口型/现成走路动画（2-3 天）→ 低配设备帧率与时延实测（1-2 天），合计约一周即可拿到全部决策依据

### 5.5.4 审美对标修正与讨论建档（2026-09-23 白机，院长五轮裁决）

**① 审美对标：原神 → 鸣潮（院长原话："原神的画风过于卡通"）**
- 鸣潮引擎核实为 **UE4.26（不是 Unity；原神才是 Unity）**，2024-05-23 公测；官方画风定位原话"既非常见赛璐璐卡渲、也非纯 PBR，介于两者之间"——二次元写实/半写实
- 渲染架构（Unreal Fest Shanghai 2023 官方分享 + RenderDoc 逆向）：**延迟管线"角色 NPR + 场景 PBR"双轨**（Stencil 区分光照分支）+ 角色独立光照管线（TOD 曲线亮度补偿/角色专属阴影图）+ 后处理（SSR/GTAO/TAAU）；移动端 deferred 1.5GB/s 跑 60fps
- 与原神差异：头身比更接近真人、面部更写实、服饰 PBR 属性更强、环境光影写实度更高
- **对诺诺的含义**：§5.5.3 中"MToon=VRChat 干净卡通"仅为 PoC 起点，不是审美目标；VRoid 捏模往写实比例调（去默认萌系脸），材质/光影向双轨靠拢；复刻难点排序=高精度角色资产 > 双轨整合 > 角色独立光照（不脏脸）> 后处理。单房间项目大世界优化项可全砍

**② 桌面端定位再明确**：长期保留，目标=**离线版游戏服务**给到朋友（单机状态权威+本地存档；AI 走用户自配 key 直连或本地小模型）；与共享直播间是两条产品线，共用美术/动作资产

**③ 讨论过程建档**：完整探讨路径（五轮讨论+被否决方向清单+架构专题解答）见 [R-058诺诺模块讨论过程](./R-058诺诺模块讨论过程.md)——院长 2026-09-23 指示"哪怕定版了，这些讨论也是有价值的思考"

**④ 架构常识（院长提问后固化）**：本地 GPU 渲染的依据="画面是谁算的"（渲染=模型+本机显卡，20 人各算各的）与"世界状态谁说了算"（服务器权威：状态/同步/密钥/持久化）分离；服务器 GPU 渲染仅云游戏场景需要（设备跑不动时推视频流，按小时烧钱），本项目不需要

### 5.6 风险与红线

1. **数据安全**：Q宠 2018 停运清档是"一代人青春记忆"级反面教材——宠物数据从第一天就设计备份/导出（prod.db 常规备份覆盖即可，但要有意识地纳入）
2. **AI 成本红线**：AGENTS 禁止事项第 5 条管的是生图/生视频 API；宠物对话用 llm.js 既有通道不触发该红线，但**生图（宠物形象/明信片配图）必须走黑机 Seedream 管线且逐次呈院长确认**
3. **性格漂移**：AI 长对话人设漂移是已知风险，阶段反思重申基线 + L1 记忆限长重写双保险
4. **不过度设计**：不引入向量数据库（20 人规模 LIKE+时间+重要度够用）、不上 BIG5 参数化（无产品背书）、不做常驻桌面端（网站形态）
