# ADR-008：剧本文案与逻辑分离

> 状态：Accepted | 决策人：陈梓键（院长） | 日期：2026-07-30
> 关联：ADR-006（视觉小说引擎选型）、src/visualnovel/data/

## 背景

M-G1 引擎核心 PoC 完成后，序章四幕全量落地，剧本数据集中在 `prologue.js`（1454 行 / 129 节点）。
问题：**文案（台词/选项/输入提示）和引擎逻辑（背景图/立绘/跳转/好感度/分支条件）焊死在同一个 JS 文件里**。

院长要微调台词时，必须在 1454 行里定位到那行 `text:`，极易碰坏周围的 `next:`/`effects:`/`branches:` 等逻辑字段。
ADR-006 曾设想「JSON 数据文件，白机黑机都能编辑」，但实际演进中 JSON 不支持注释——改文案时看不到"这句是谁说的/什么场景"，可读性差。

### 约束条件

1. **院长能独立改台词**：不碰代码逻辑，不依赖 AI
2. **改完立刻生效**：不需要编译/构建，Vite HMR 热更新
3. **旧存档兼容**：不能因重构让玩家存档作废
4. **支持注释**：文案文件要能标注说话人/场景，方便定位
5. **多章节可扩展**：后续第一章、第二章要能平滑接入

## 决策

**采用「逻辑骨架 + 文案分离 + 运行时合并」方案**：

- `prologue.js` 只保留逻辑骨架（type/background/characters/next/effects/branches 等），删除所有文案字段
- 新建 `data/scripts/` 目录，按幕拆分文案文件（`.script.js`），每个文案带说话人/场景注释
- 引擎层新增 `mergeScript()` 纯函数，章节加载时按节点 id 把文案注入骨架
- 文案文件用 **JS 数组**（非 JSON），支持中文注释，Vite 原生 import

## 替代方案

### 方案B：纯 JSON 文案 + JSON Schema

- 做法：文案抽到 `.json`，js 引用 JSON
- 优势：标准格式，可被任意工具解析
- 劣势：**JSON 不支持注释**，改文案时看不到说话人/场景上下文，可读性差
- **否决理由**：违背约束4（支持注释），院长改文案体验差

### 方案C：文案放 Markdown + 脚本同步

- 做法：文案放 `.md`（带说话人标注），写脚本从 md 解析注入 js
- 优势：可读性最好，像读剧本
- 劣势：① md 和 js 会漂移（双份维护）② 解析脚本要处理多种节点类型，脆弱 ③ 增加构建步骤
- **否决理由**：违背"单一数据源"原则，维护成本高

## 决策依据

| 维度 | JS 文案分离（采纳） | JSON（方案B） | Markdown+脚本（方案C） |
|------|:---:|:---:|:---:|
| 支持注释 | ✅ | ❌ | ✅ |
| 改完即生效 | ✅ HMR | ✅ HMR | ⚠️ 需跑脚本 |
| 单一数据源 | ✅ | ✅ | ❌ 双份 |
| 可读性 | ✅ 好 | ⚠️ 一般 | ✅ 最好 |
| 实现成本 | ✅ 低（1个纯函数） | ✅ 低 | ⚠️ 中（解析脚本） |

## 影响

### 新增
- `src/visualnovel/data/scripts/` 目录（4 个按幕拆分的文案文件 + README 操作指南）
- `engine.js` 新增 `mergeScript()` 纯函数（按 id 合并文案到骨架）
- `engine.js` 新增 `interpolate()` 通用插值函数（替代硬编码的 `{playerName}` replace，支持任意变量）

### 修改
- `prologue.js`：删除全部 text/placeholder/choices文案，变为纯逻辑骨架（仍保留幕/场景注释 + 节点 id + 全部逻辑字段）
- `visualNovelStore.js`：`CHAPTER_LOADERS.prologue` 从单 import 改为多 import + mergeScript 合并
- `visualNovelStore.js`：插值点从 `replace(/\{playerName\}/g)` 改为通用 `interpolate()`
- 4 份历史台词 md 标注为「历史创作稿」，运行文案以 scripts/ 为准

### 兼容性
- **旧存档 100% 兼容**：存档只存节点 id 字符串，id（pro_001~pro_end）未变
- **choice 选项顺序不变**：合并按下标对应，保持原序

### 对 ADR-006 的演进
ADR-006 设想「JSON 数据文件」，本 ADR 细化为「JS 文案文件（支持注释）+ 逻辑骨架分离」。
原因：实测后发现 JSON 无注释导致文案可读性差，JS 兼顾可读性与原生 import。
