# ADR-007：德塔视觉小说 音频管线方案

> 状态：Accepted（低优先级，待文案完善后启动） | 决策人：陈梓键（院长） | 日期：2026-07-29
> 关联：R-024（配音+配乐系统）、R-025（进入防呆弹窗）、ADR-006（视觉小说引擎选型）

## 背景

视觉小说引擎 M-G1 PoC 已验证通过（纯文本+立绘+背景），下一步提升观感需要加入配音和配乐。院长提出配音优先级较低，等文案完善、全流程打通后再做，避免改剧本导致配音返工。服务器只有 40G 存储，音频资源可能需要外挂对象存储。

### 约束条件

1. **配音延后**：等文案定稿后再做，不为未定的剧本配音
2. **存储有限**：服务器 40G 盘，音频文件可能需要 OSS/COS 外挂
3. **用户端零依赖**：玩家浏览器直接播放，不装插件
4. **摸鱼防呆**：用户多在摸鱼时点进，需每次提醒是否开启声音（R-025）

## 决策

**三层架构：生成层（离线）→ 处理层（离线）→ 运行层（线上）**

### 层1：生成层（黑机离线工具）

| 用途 | 工具方案 | 说明 |
|------|---------|------|
| 配音（TTS） | Edge TTS / CosyVoice / GPT-SoVITS | 文本→语音，Edge TTS 最省事，CosyVoice/GPT-SoVITS 可克隆音色但需 GPU |
| 配乐（BGM） | Suno / Udio | 在线平台生成制作级 BGM，~$10/月 |
| 免版权素材 | 素材库 | 备选，最快最省但风格有限 |

### 层2：处理层（黑机离线工具）

| 用途 | 工具 | 说明 |
|------|------|------|
| 转码/标准化 | FFmpeg | wav→mp3 128k，统一格式 |
| 拼接/裁剪 | FFmpeg | 多段配音拼接、BGM 裁剪 |
| 淡入淡出 | FFmpeg | `afade` 滤镜 |
| 混音 | FFmpeg | 语音+BGM 混音 `amix` |
| 音量标准化 | FFmpeg | `volume` 滤镜 |

**Node.js 集成**：`ffmpeg-static`（自带二进制）+ `child_process`，零环境配置。

### 层3：运行层（白机线上）

| 用途 | 方案 | 说明 |
|------|------|------|
| 语音播放 | `<audio>` 标签 | 引擎进入节点，若有 voice 字段则播放预生成 mp3 |
| BGM 播放 | `<audio>` + 淡入淡出 | 节点 bgm 字段切换时交叉淡入 |
| 进入防呆 | 弹窗组件 | 每次进入 /nde 提醒是否开启配音+配乐（R-025） |

### 数据结构扩展

剧本节点（prologue.js 等）新增可选字段：
```js
{
  id: 'pro_009',
  type: 'dialogue',
  voice: 'voices/pro_009.mp3',  // 配音文件路径
  bgm: 'bgm/empire_theme.mp3',  // 背景音乐路径
  // ... 其他现有字段
}
```

### 文件存放

```
public/visualnovel/
  ├── voices/     # 配音 mp3
  └── bgm/        # 背景音乐 mp3
```

## 替代方案

### 方案B：ffmpeg.wasm 浏览器端处理

- 优势：用户端实时处理，无需预生成
- 劣势：① WASM 核心约 25MB，加载慢 ② WebGPU/多线程要求高 ③ 20人朋友圈设备参差
- **否决理由**：预生成方案更轻量，用户端只需 `<audio>` 播放

### 方案C：Timeline Studio（ai-video-editor）

- 优势：内置 AI 配音（Piper/VITS）+ 视频编辑
- 劣势：① React 项目，与 Vue 3 技术栈冲突 ② 完整视频编辑器体量过重 ③ WebGPU 依赖重
- **否决理由**：技术栈不兼容 + 功能远超需求

## 备注

- **优先级低**：等文案完善、全流程打通后启动
- **存储方案**：40G 盘可能不够，届时考虑 OSS/COS 对象存储外挂
- **TTS 工具选型**：启动时再定，Edge TTS（免费省事）vs CosyVoice/GPT-SoVITS（可克隆音色需 GPU）
- **许可证**：FFmpeg 默认 LGPL-2.1+（音频处理无 GPL 风险）；Suno/Udio 生成的音乐需确认商用授权
