# 记忆注入注意力分散调研

> 调研时间：2026-09-24（白机，子 Agent 执行+主 Agent 落档）
> 背景：诺诺记忆系统 v2 设计的前置专项——院长提出"注入的记忆存档可能把 agent 注意力转移到不重点的地方"。本调研核实该风险的学术证据与业界注意力管理实践。
> 用途：《自习室·记忆系统设计》的注意力管理规范依据。关联：[R-058诺诺模块讨论过程](../03-产品与游戏设计/R-058诺诺模块讨论过程.md) 第十一轮。

---

## 一、核心结论（先看这个）

1. **院长的担忧有硬核学术实锤**：SIGIR 2024《The Power of Noise》——仅注入 1 个"看似相关但不含答案"的记忆条目，准确率降 19%；Chroma《Context Rot》进一步区分：**"与用户主题相关但不回答当下问题"的记忆比完全无关的内容是更恶劣的干扰源**——这精确对应诺诺的场景（检索出的用户记忆大概率"与用户相关"，但未必与当下问题相关）。
2. **位置有 U 型曲线**（Lost in the Middle, TACL 2023）：相关信息在开头 75.8% / 结尾 63.2% / 中部 53.8%，最差情形甚至低于不塞任何上下文的闭卷基线（56.1%）——"塞了反而不如不塞"。
3. **指令后置优于前置**（+9.7 BLEU，arXiv:2308.12097）：长输入稀释对指令的注意力——记忆放前、当前问题与指令放最后。
4. **注入规模 3-5 条最佳**（Power of Noise）：再多半相关记忆线性放大干扰；聚焦小上下文（~300 token 级）全面优于大而全（113k，Context Rot 18 模型实测）。
5. **"忽略无关信息"的显式指令有效**（GSM-IC, ICML 2023）：给记忆块加措辞框架（"背景参考，仅相关时使用"）是被验证的缓解手段。
6. **业界收敛点**：小而稳的核心画像常驻（MemGPT working context / Letta memory blocks）+ 交互细节按需检索（Claude Memory Tool 的 just-in-time 理念）；混合策略优于纯被动注入或纯工具式（Anthropic 提醒 agentic search 延迟更高，与本项目"实时性红线"冲突——工具式 recall 需谨慎）。

## 二、论文证据明细

| 论文/报告 | 核心数字 | 对诺诺的含义 |
|---|---|---|
| Lost in the Middle（TACL 2023, arXiv:2307.03172） | 首位 75.8% vs 中部 53.8%（低于闭卷 56.1%）；文档 20→50 篇仅 +1.5% | 记忆放 prompt 前部；"多塞"无边际收益 |
| GSM-IC（ICML 2023, arXiv:2302.00093） | 无关句子大幅拉低推理；"忽略无关信息"指令有效 | 措辞框架是必选项 |
| Power of Noise（SIGIR 2024, arXiv:2401.14887） | 1 个 distractor -19%（峰值 -25%，18 个 -67%）；k=3-5 最佳；distractor 近 query 伤害最轻 | 检索分高≠该注入；条数硬上限 |
| Context Rot（Chroma 2025-07，18 模型 19.4 万调用） | 单个干扰项即可降性能；"主题相关但不回答"最恶劣；300 token 聚焦 >> 113k 全量 | 半相关记忆是最危险的注入物 |
| LongMemEval（ICLR 2025, arXiv:2410.10813） | 持续交互记忆任务准确率降 ~30%；索引/检索/阅读三阶段优化 | 上线前可做"拒答/知识更新"两维自测 |
| Instruction Position（arXiv:2308.12097） | 指令后置 +9.7 BLEU（1B-13B 稳定） | 问题与指令放 prompt 末尾 |
| CMI（arXiv:2608.07622，2026-08） | 干扰通过"阻断暴露/破坏下游使用"两路径；记忆需权威性/时间元数据 | 存档条目要带时间戳与新旧权威标记 |
| MemGauge（arXiv:2608.30177，2026-08，11 模型） | 写入准入有阈值式风险跳变；检索暴露效用与风险同步增长 | 写入门槛宁缺毋滥；过滤质量决定成败 |

## 三、业界实践要点

- **MemGPT/Letta**：working context 固定小预算常驻（自编辑）+ archival 工具按需检索分页；70% 用量触发自主固化——"小核心常驻+大库按需"鼻祖
- **mem0**（源码级核实）：检索默认 top_k=20 + threshold=0.1 + 语义/BM25/实体三信号融合打分 + 过期剔除；2026-04 改单遍 ADD-only（写入简单化，检索侧做厚过滤）
- **Claude Memory Tool**：文件系统式记忆 + just-in-time retrieval + 官方自动注入"先 view 记忆再干活"指令；**但 agentic search 延迟高于预载**（Anthropic 官方提醒）——与本项目实时性红线冲突，工具式 recall 二期再议
- **Anthropic 上下文工程**（2025-09 原文）：compaction 过度压缩会丢关键细节；推荐 structured note-taking（笔记写窗口外、需要时拉回）

## 四、注意力管理设计规范（v2 设计文档引用）

1. 注入前相关性硬过滤，宁少勿多（1 个半相关条目 -19%）
2. 检索查询必须携带当轮用户问题语义，不按"用户画像"泛检索（防"主题相关但不回答"型干扰）
3. 记忆放前部 / 问题与指令放末尾
4. 检索条目 3-5 条硬上限；存档总注入控制在一屏文本量级
5. 小核心常驻（画像）+ 细节按需（互动历史）分层
6. 措辞框架："背景参考，仅在与当前问题相关时使用，否则忽略"+ 结构化标签包裹
7. 记忆条目带时间戳与权威性元数据（新事实可覆盖旧事实）
8. 写入侧设门槛（MemGauge 阈值跳变）——寒暄/琐事不入档
9. 工具式 recall（agent 自主查记忆）延迟与实时性冲突，二期评估
10. 上线前用 LongMemEval 式"拒答/知识更新"探测自测
