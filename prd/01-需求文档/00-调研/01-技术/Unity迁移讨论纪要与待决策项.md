## 一、背景：院长为什么提 Unity（四点论据，白机 AI 已认账）

白机 AI 最初建议"留 Web 不迁移"，院长四点反驳**全部成立**，白机立场已修正为**支持迁 Unity、原型先行**：

1. **零门槛访问无所谓**——可直接做客户端打包 exe 给朋友们（产品形态由院长定，Web 门户零门槛论据撤回）；
2. **性能反超**——现线上服务器 2G2 核，单机应用直接用**机主本人配置**（游戏 PC）跑渲染/物理/推理，性能天花板解除；
3. **联网最小化**——只有云端 LLM API 需要联网；本地部署模型（Ollama/LLMUnity）可实现**完全离线单机**；
4. **技术积累就是拿来学习的**——项目本身是练手，换 Unity 学 C#/Unity 管线/端游工程化是学习增量（"重写浪费"论据在练手定位前不成立）。

白机补充并被院长认可的证据：**Blender 步态 clip 在 Web 端流畅播放**已证明"动捕级动作+轻运行时"可行——迁移的动机不是"Web 做不了"，而是院长对产品形态（单机/性能/离线）与学习价值的主动选择。

## 二、黑白机协作方案（院长核心关切，已有完整方案）

约束：**白机=公司电脑，不装 Unity**；黑机=RTX 4070+可装 Unity。

| 层 | 内容 | 归属 |
|---|---|---|
| Unity 编辑器内 | 场景/材质/动画/组件配置/打包 exe | **黑机** |
| C# 脚本 | 大脑对接、动作状态机、配方解释器、WebSocket | **白机**（VSCode 写文本，无需 Unity） |
| 数据层 | 动作配方 JSON、语义 schema、场景坐标 | 白机写、黑机验证 |
| 大脑服务 | LLM/感官/记忆（Node/Python） | 白机（与现在完全相同） |

- **与现行分工口径完全同构**（黑机=编辑器内工作替代"Blender/Krita 实操"，白机=代码/数据/文档不变）；
- **白机失去"运行验证"的缓解**：①数据驱动（动作/交互全走配方 JSON，C# 只写解释器——白机 80% 产出仍即时可验证）②黑机每晚首件事=编译白机日间产出+反馈清单 ③白机验证重心前移到协议与大脑服务（可独立联调）；
- **MCP 闭合编辑器缺口（调研确认）**：Unity 官方 **CLI/MCP Server 免费无并发限制**（Unity 6+），或社区 unity-mcp（14.8k stars）——**白机 AI 可远程操作黑机的 Unity 编辑器**，双机都能驱动。

## 三、工程结构（已讨论定案方向）

- **独立文件夹+独立 git 仓**（如 `D:\product\nande-unity`，与 nande 平级；GitHub 私有仓）——Unity 不能"打开"现成仓库目录（必须 Unity 工程骨架），nande 内嵌子目录会生成数 GB Library 缓存拖垮 vite watcher/git，且 nande 刚做完体积治理；
- **Git LFS** 管二进制大件（VRM/FBX/贴图），文本（.cs/.json/场景 YAML）普通 git；
- **白机一次性配置 `git lfs install --skip-smudge`**——pull 永久跳过大件只取指针，实现"白机只处理文本和代码，不全量拉取"（院长要求 ✓；需要大件时 `git lfs pull --include=<路径>` 单拉）;
- **LFS 额度**：GitHub 免费 1GB 存储+1GB/月流量——原型期 <200MB 够用；**沿用美术纪律（定版入库/过程版本黑机本地）压增量**；超限时（GitHub 页可见用量）再议 $5/月 Data Pack 或迁移，届时请示院长；单文件上限 2GB（VRM 远不到）;
- **场景(.unity)文件 merge 易冲突**——场景归黑机单人管，prefab 拆小；白机只碰 .cs/.json;
- **大脑服务留 nande 仓**，Unity 客户端经协议访问——协议契约（接口 schema+版本号）双仓引用。

## 四、调研结论（详见两份调研文档，此处只列与迁移直接相关的）

- **UniVRM 原生支持 .vrma**——Blender 步态 clip 零改动平移（原"需改 FBX 导出"的判断作废）；VRM/blendshape/弹簧骨/Krita 内嵌贴图全支持；
- **AI 写 Unity C# 官方已下场**：Unity 官方 Claude Code/Codex/Grok 插件+CLI+MCP Server 免费档；公认坑=AI 不识场景依赖（MCP 解法）;
- **离线大脑**：LLMUnity（llama.cpp 本地推理，RAG+函数调用）是主流；Sentis/Inference Engine 跑 LLM 非主流;
- **近乎定制的参考架构**：**ChatdollKit**（VRM 语音对话 SDK：口型/表情/动作同步+STT/TTS+多 LLM+AITuber 模式）——可基于其架构起步;
- **成本**：Unity Personal 免费+CLI/MCP 免费档+LLMUnity/Ollama 免费=**全程零订阅**;
- **世界模型调研衔接**：诺诺"结构化世界模型"架构（L1 快照+实体化+配方）引擎无关、思想平移；院长表态空白带=开拓者路径，保持结构化状态表示即保住门票。
