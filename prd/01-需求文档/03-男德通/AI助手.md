## 1. Why-Who-What

- **业务背景**：男德学院为朋友圈限定社区（21 人），微信群沉淀 53.8 万条聊天记录（2022-07 至今）。男德通是社区网站的 AI 助手，用自然语言查询群聊数据、闲聊、查设定、提反馈
- **目标用户**：全部登录成员（约 20 人）
- **当前形态**（v3.5.0）：多 Agent 三阶段架构（规划→并行检索→分析回答）+ 4 套人设 + 图片理解 + 记忆压缩 + 多轮追问

## 2. 核心架构（2026-08-11 起）

主 Agent（orchestrator）持有对话上下文，按需派发子 Agent：

| 子 Agent | 职责 | 数据源 |
|---|---|---|
| person_stat | 人物统计（发言数/活跃月/长度） | SQL 直查（无 LLM） |
| person_messages | 人物发言检索（含上下文） | 精确匹配 nickname |
| mentioned | 被提及检索（别人提到某人） | content LIKE（模糊是职责要求） |
| topic_search | 话题检索（同义词扩展+FTS5 v2 四级降级+块内抽样） | message_chunks + FTS5 |
| time_search | 时间范围检索（按日/月聚合+话题块摘要） | message_chunks |
| worldbook | 德塔世界观设定集（3 万字按需注入） | 设定集 v1.4 文件 |
| db_info | 数据库元信息（总数/跨度/排行/版本） | SQL 直查（无 LLM） |
| 视觉识别 | 用户发图先识别（150 字中文描述） | doubao-seed-2-0-mini |

已弃用（保留工程参考）：semanticAgent（被 topic+time 替代）、statisticAgent（被直查 SQL 替代，避免幻觉）。

## 3. 路由策略（四级短路）

1. **视觉识别**：带图必跑，识别结果注入问题
2. **闲聊短路**：≤10 字 + 匹配词表；情绪反应词（哈哈哈/笑死）有上下文时不短路
3. **快速路由**：正则模板匹配高频问题（"XX发了多少条"等），跳过规划 LLM
4. **LLM 规划**：glm-5.3 temp=0 输出 JSON 任务数组，追问"还有呢"注入 lastIntent

## 4. 人设系统

基础模板中性化（身份+知识+数据规则），语气由 4 套预设独立定义：
**正常人（默认）**/体委/丘比/开开 + 自定义。详见 persona.js。

## 5. 数据与检索

- 消息 538,915 条 / 分块 5,372 个（100 条/块，LLM 生成 keywords+summary）
- FTS5 v2（2026-08-21 方案A）：unicode61 + 预分词（≤4 字整词 + 长词 bigram 滑窗），2 字中文词可命中
- 旧 trigram 表保留作回退，v2 稳定后清理

## 6. 记忆与上下文

- 短期：最近 19 轮原文注入
- 压缩（痛点21）：超 20 turns 自动摘要早期轮次存 ChatSession.summary，注入 system 消息；前端显示"更早对话已压缩"提示条
- 追问（痛点22）：lastIntent 注入规划 prompt

## 7. 关键约束（红线）

- **数据规则**：群聊数据必须基于检索结果，禁止编造数字/人名/发言
- **出图红线**：AI 生成 API 必须院长逐次确认提示词（AGENTS 禁止事项第 5 条）
- **db 纪律**：服务器 DATABASE_URL 指向 prod.db，操作错库已致 3 次事故（BUG-61/65/70）
