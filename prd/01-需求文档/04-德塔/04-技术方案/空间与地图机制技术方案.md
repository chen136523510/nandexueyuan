## 一、目标

打穿三级空间模型的技术底座，让"玩家在某个地点、可以去哪些地方、地点里能干什么"由**数据驱动**，而不是在剧本里逐个写死节点：

```
塔楼内部（房间级）→ 区域（草原/帝国/共和国…）→ 大陆（地图级）
```

本阶段落地：**塔楼内部房间级**（用第三幕过渡段做验收场景）；区域级/大陆级预留数据模型，后续随 R-022 展开。

## 三、核心设计：地点 = 带状态的"舞台坐标"

剧情（节点图，时间线）与空间（地点图，坐标）**解耦**：

- **剧情**：仍是节点图推进（goToNode），节点可声明 `location` 字段（可选）——进入节点时自动同步当前位置
- **空间**：地点图（locations.js），每个地点有背景/热点/出口/状态
- **衔接**：**`explore` 是节点属性（dialogue/end 均可带），不是节点类型**——任何节点带 `explore: true` + `location` 即进入该地点的探索态；探索态热点 goto 剧情节点即恢复剧情。**剧情内部随时可进探索态，探索态随时可被剧情打断，双向可达**

状态机：

```
剧情模式（currentLocation=null） ⇄ 探索模式（currentLocation='hall'）
   goToNode 推进（节点无 explore 字段）       节点带 explore: true + location 进入
   热点 goto 剧情节点（自然回到剧情模式）      出口 travelTo（切到另一地点探索态）
   剧情链尾节点带 explore → 回到探索态
```

**关键性质**：
1. **探索态可在剧情任意位置进入**——"一段情节结束"只是最常见用法（end 节点带 explore）；"剧情中间突然可自由活动"（dialogue 节点带 explore）同样支持，无需改引擎
2. **探索态非静默**——地点可配 `onEnter` 进入演出（旁白链）；探索中触发对话 = 热点 goto 剧情节点链，链尾节点带 `explore` 自动回到探索态（返回点由 explore 属性天然承担，无需额外机制）；出口 travelTo 也可配过渡演出
3. **探索态的实现 = 合成节点**——进入探索态时 store 内部生成合成节点 `{ type:'explore', location:'hall' }`，渲染层照旧读 currentNode（背景取 location.bg、无文本、热点显示），**渲染路径与剧情模式共用，改动最小**；有对话发生时 goto 真实剧情节点，对话框自然出现

## 八、风险与决策点

| 决策点 | 方案 | 理由 |
|---|---|---|
| explore 的载体 | **节点属性（dialogue/end 均可带），非节点类型** | 剧情内部可随时进出探索态；"情节结束后探索"只是最常见用法；链尾带 explore 天然充当"返回点"，无需额外机制 |
| 探索态实现 | **合成节点**（进入时生成 `{type:'explore', location}`，渲染层照旧读 currentNode） | 渲染路径与剧情模式共用，对话框/立绘/背景逻辑零重复；有对话时 goto 真实节点自然显示对话框 |
| 探索态是否可存档 | 可存档（空间字段入快照） | 与"存档恢复=回到上次进度"的产品一致 |
| 出口条件语法 | 复用 condition 的 variables/affinity 语法 | 一套条件引擎，不发明新语法 |
| 探索态对话框 | 无文本时隐藏，地点 desc 显示为顶部横幅；进入/切换地点的旁白走 onEnter 演出链 | 视觉语义清晰；对话/旁白场景由剧情链承载，不在探索态硬塞 UI |
