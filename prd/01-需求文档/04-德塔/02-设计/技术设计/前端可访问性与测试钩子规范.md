# 前端可访问性与测试钩子规范

> 适用范围：全项目前端（`src/`），重点为德塔视觉小说模块（`src/visualnovel/`）
> 创建：2026-08-10
> 关联调研：`prd/01-需求文档/00-调研/GUI自动化测试与前端可访问性调研.md`

---

## 一、为什么需要这个规范

GUI 自动化测试（含 Playwright E2E 与 AI 驱动的浏览器测试）遇到两大痛点：

1. **图标按钮定位难**：图标按钮（emoji/符号/SVG，无可见文字）只能靠脆弱的 CSS class 定位，改个 class 测试就挂。
2. **屏幕阅读器误读**：纯符号按钮（如 `✕`）会被读成"乘号"，视障用户/无障碍工具无法理解。

**解决思路**：强制所有图标按钮带语义化属性，让测试能精准定位、让辅助技术能正确朗读。一个属性同时解决两个问题。

---

## 二、核心规则（强制）

### 规则 1：图标按钮必须有 `aria-label` 或 `data-testid`

所有**无可见文字**或**仅含图标**（emoji / 符号 / SVG）的 `<button>`，**必须**满足以下任一：

| 属性 | 优先级 | 作用 |
|---|---|---|
| `aria-label="中文描述"` | **首选** | 屏幕阅读器朗读 + 测试 `getByRole('button', { name })` 定位 |
| `data-testid="kebab-case-id"` | **补充** | 测试 `getByTestId` 精准定位，不受文案改动影响 |

两者可并存。**推荐两者都加**：aria-label 供无障碍，data-testid 供测试稳定定位。

### 规则 2：有可见文字的按钮可豁免 aria-label，但建议加 data-testid

含完整可见文字的按钮（如「存档」「读档」），文字本身就是 accessible name，无需重复 aria-label。但涉及测试关键路径的按钮仍建议加 data-testid 以隔离文案改动影响。

### 规则 3：禁止裸符号按钮

禁止用 `✕` `×` `▶` 等符号作为按钮**唯一内容**而不加 aria-label。屏幕阅读器会读成"乘号""大于号"等无意义内容。

## 三、各场景细则

### 3.1 纯图标按钮（emoji / 符号）

```html
<!-- ❌ 错误：裸符号，屏幕阅读器读"乘号"，测试只能靠 class -->
<button class="close-btn" @click="close">✕</button>

<!-- ✅ 正确：aria-label + data-testid -->
<button class="close-btn" aria-label="关闭" data-testid="close-btn" @click="close">✕</button>
```

### 3.2 Emoji 图标按钮

```html
<!-- ❌ 错误：仅 title，测试无法 getByRole 定位 -->
<button :title="btn.label" @click="btn.action">
  <span class="icon">{{ btn.icon }}</span>
</button>

<!-- ✅ 正确：aria-label 同 label，测试可 getByRole -->
<button :aria-label="btn.label" :data-testid="`${btn.id}-btn`" :title="btn.label" @click="btn.action">
  <span class="icon">{{ btn.icon }}</span>
</button>
```

### 3.3 Toggle 按钮（开/关）

```html
<!-- ✅ 加 role="switch" + aria-pressed -->
<button class="toggle" role="switch" :aria-pressed="isOn" @click="toggle">
  {{ isOn ? '开' : '关' }}
</button>
```

### 3.4 SVG 图标按钮（未来 lucide-vue-next 场景）

```html
<!-- ✅ SVG 图标按钮，aria-label 描述动作 -->
<button aria-label="设置" data-testid="settings-btn" @click="openSettings">
  <SettingsIcon />
</button>
```

### 3.5 弹窗 Overlay（dialog 语义）

```html
<!-- ✅ 加 role="dialog" + aria-modal -->
<div class="overlay" role="dialog" aria-modal="true" @click.self="close">
  <div class="panel">...</div>
</div>
```

### 3.6 文件上传 hidden input

```html
<!-- ✅ 父 label 加 aria-label，input 保持 hidden -->
<label class="upload-label" aria-label="上传图片">
  📷 图片
  <input type="file" accept="image/*" @change="onSelect" hidden />
</label>
```

## 四、data-testid 命名约定

| 格式 | 示例 |
|---|---|
| `{模块}-{元素}-{动作/用途}` | `vn-save-btn` / `wall-image-input` / `vn-close-btn` |

**模块前缀**：
- `vn-` 视觉小说模块（visualnovel）
- `wall-` 师德墙
- `chat-` 群聊
- `admin-` 管理后台
- `nav-` 导航

**约定**：
- 全小写 kebab-case
- 动作用 `btn`/`input`/`tab`/`link` 等通用词，不写具体文案（文案会变，testid 不变）
- 一组同类按钮（如 5 个 QuickMenu 按钮）用 `{模块}-{功能}-btn` 统一前缀，测试可用正则/前缀匹配批量定位

## 五、自动化测试定位优先级

测试代码定位元素时，按以下优先级（稳定性从高到低）：

| 优先级 | 方法 | 代码 | 适用 |
|---|---|---|---|
| 1 | **getByTestId** | `page.getByTestId('vn-close-btn')` | 最稳定，不受文案/结构变动影响 |
| 2 | **getByRole + name** | `page.getByRole('button', { name: '关闭' })` | 走 aria-label，语义化 |
| 3 | **getByLabel** | `page.getByLabel('上传图片')` | 表单 label 关联 |
| 4 | **getByText** | `page.getByText('存档')` | 有可见文字时 |
| 5 | CSS class（兜底） | `page.locator('.close-btn')` | **不推荐**，class 改动即失效 |

> `tests/e2e/utils.js` 的 `clickIconBtn()` 已封装此优先级逻辑，测试代码直接调用。

## 六、强制检查

项目内置扫描脚本 `scripts/check-a11y.mjs`，检测所有图标按钮是否带语义化属性：

```bash
npm run lint:a11y
```

- 缺 `aria-label` 且缺 `data-testid` 的图标按钮会报错（非零退出）
- 建议在提交前运行，或接入 pre-commit / CI
