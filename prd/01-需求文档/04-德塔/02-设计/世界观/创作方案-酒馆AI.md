经探查，火山引擎 coding plan 端点（`/api/coding/v3`）虽支持 `deepseek-v4-pro`，但 ST 原配置用的是 glm-5.1。经用户确认，改用 **DeepSeek 官方 API**，配置更简洁、模型名固定。

| 项 | 值 |
|----|----|
| **base_url** | `https://api.deepseek.com` |
| **chat 端点** | `https://api.deepseek.com/v1/chat/completions` |
| **模型 ID** | `deepseek-v4-pro`（推理模型，思考过程在 `reasoning_content`，正式回复在 `content`） |
| **认证** | `Authorization: Bearer sk-xxx` |

## 六、技术踩坑记录（已解决，供后续参考）

搭建过程中踩了 3 个坑，均已解决，记录如下避免重复踩坑：

### 坑 1：ST 角色卡必须是 PNG 格式（不读纯 JSON）

**现象**：角色卡 `.json` 放进 characters 目录后，ST 角色列表不显示。

**根因**：ST 源码 `characters.js:1466` 只扫描 `.png` 文件，角色卡数据（角色名、人设、开场白）必须以 base64 编码嵌在 PNG 图片的 `chara` tEXt chunk 里（这是 SillyTavern Character Card v2/v3 标准）。纯 JSON 文件被忽略。

**解决**：用 ST 源码自带的 `character-card-parser.js` 的 `write()` 函数生成角色卡 PNG——载体 PNG + 角色 JSON → 注入 chara chunk。用 `read()`/`parse()` 回读验证通过。

**结论**：以后生成 ST 角色卡，必须走 PNG 注入流程，不能放纯 JSON。

### 坑 2：ST config.yaml 读取的是本体目录，不是 dataRoot

**现象**：config.yaml 里 `port: 11451`，但 ST 实际监听 8000。

**根因**：ST 启动日志 `Using config path: ./config.yaml`——config 路径是相对 cwd（本体目录），不受 `--dataRoot` 影响。本体目录的 config.yaml 里 `port: 8000`、`browserLaunch.port: -1`（自动选端口），覆盖了 st_data 里的配置。

**解决**：接受 ST 在 8000 端口运行。正常用 Launcher GUI 启动不受此影响（Launcher 用自己的端口管理）。

### 坑 3：deepseek-v4-pro 是推理模型，max_tokens 要给足

**现象**：max_tokens=200 时回复内容为空。

**根因**：推理模型的思考过程（reasoning_content）也算 token。200 token 全被思考过程消耗，正式回复（content）没额度。

**解决**：`openai_max_tokens` 设为 8192，给思考过程和正式回复都留足空间。
