# 德塔形态重构战略规划（横版像素 → 等距俯视手绘风）

> 状态：Accepted（院长 2026-07-28 确认方向锁定）| 决策人：陈梓键（院长） | 日期：2026-07-27
> 关联：ADR-005（世界观承载方式，预留2D俯视角升级路径）、设定集 v1.3、R-009 战斗系统
> 性质：战略级里程碑规划，非实施指令。每个里程碑启动前需院长确认。

## 0. 背景与决策依据

### 0.1 院长决策（2026-07-27）

- **方向**：德塔从"横版像素风"重构为"等距俯视角 + 环境氛围叙事 + 分层美术方案"
- **三个维度都要**：① 等距俯视信息密度 ② 环境氛围叙事（昼夜/天气/光影）③ 分层美术方案（立绘/漫画=美漫厚涂，精灵=Q版/低分辨率）
- **资产态度**：现有横版像素资产（R-003 精灵表等）可接受推倒，"船小好掉头"
- **前提**：先做战略规划（里程碑），不立即开发
- **深层诉求**：需要项目管理机制，保证 AI 新窗口能轻松接手进度

### 0.2 与 ADR-005 的关系

ADR-005 决策3末尾明确保留："若未来确有'更沉浸的探索'需求，优先在 2D 内升级（如 2D 俯视角），而非切 3D"。本规划即走这条预留路径，**不违背 ADR-005**，但需新增 ADR-006 正式锁定此方向。

### 0.3 资产损失评估

| 资产 | 复用性 | 处置 |
|---|---|---|
| 后端全部（Colyseus/Express/Prisma） | ✅ 完全复用 | 不动 |
| Vue 框架 + 业务页面（师德墙/男德通等） | ✅ 完全复用 | 不动 |
| 世界观设定集（118年/六大势力） | ✅ 完全复用 | 不动 |
| 立绘/头像 PNG | ✅ 完全复用 | 不动 |

## 1. AI 协作项目管理机制升级

### 1.1 现状诊断

本仓库已有成熟的战术级协作机制（handoff/sync-docs/ADR/release-helper），但缺少**战略级**管理：

| 层级 | 现有机制 | 缺口 |
|---|---|---|
| 战术级（单次任务） | `.ai/handoff.md` 交接单 + sync-docs 技能 | ✅ 成熟 |
| 里程碑级（版本发布） | ADR-004 版本号 + release-helper 技能 | ✅ 成熟 |
| **战略级（跨里程碑路线图）** | 无 | **❌ 缺口** |

缺口导致的 AI 接手问题：
- 新会话只看到"上次做到哪"，看不到"整体往哪走"
- AI 无法判断当前任务在整个路线图中的位置和优先级
- 探索性任务（uphill）和确定性任务（downhill）混在一起，AI 容易在未验证的假设上铺代码

### 1.2 升级方案：三层协作体系

```
战略层（本文件）     → pm/ROADMAP.md                              ← 跨里程碑路线图
里程碑层（现有）     → ADR-004 + release-helper + CHANGELOG       ← 版本快照
战术层（现有）       → .ai/handoff.md + sync-docs + AGENTS.md     ← 每次会话交接
```

### 1.3 新增文件：`ROADMAP.md`（战略级路线图）

放在 `pm/ROADMAP.md`，作为 AI 新会话接手时的**第二份必读文件**（第一份是 handoff.md）。

**结构规范**：
```markdown
# 男德学院产品路线图

## 当前里程碑：M-XXX（名称）
- 状态：uphill（探索中）/ downhill（执行中）/ completed
- 假设表：列出 2-3 个关键假设及验证状态
- 退出条件：客观可验证的标准

## 里程碑列表（倒序）
### M-XXX（最新）
### M-XXX-1（上一个）
...

## 假设登记簿
| 编号 | 假设 | 验证方法 | 状态 |
```

### 1.4 山丘图（Hill Chart）标注机制

借鉴 Shape Up 方法，每个任务标注 uphill/downhill：

| 标注 | 含义 | AI 行为 |
|---|---|---|
| ⛰️ uphill | 问题还没想清楚，方案未定 | **禁止直接写代码**，先做 PoC/调研/方案验证 |
| ⛰️ downhill | 方案已定，可预估工作量 | 可直接执行，按步骤清单推进 |

在 handoff.md 的"待办"部分，每项任务标注 uphill/downhill。

### 1.5 会话接手协议（升级版）

AI 新会话开场必读顺序：
1. `AGENTS.md`（项目纪律 + 技术栈 + 踩坑）— 已有
2. `.ai/handoff.md`（上次做到哪 + 进行中任务 + 环境状态）— 已有
3. `pm/ROADMAP.md`（整体往哪走 + 当前里程碑）— **新增**

会话结束必做：
1. 更新 `.ai/handoff.md`（进行中任务 + 进度百分比）— 已有
2. 执行 sync-docs 技能同步四文档 — 已有
3. 若里程碑状态变化，更新 `ROADMAP.md` — **新增**

## 2. 形态重构里程碑路线图

### 2.1 里程碑总览

```
M-1  等距俯视角 PoC（最小验证）                  ⛰️ uphill    ~1周
M-2  ADR-006 方向锁定 + 美术风格 PoC             ⛰️ uphill    ~1周
M-3  等距引擎重构 + 环境氛围层（坐标/碰撞/氛围）  ⛰️ downhill  ~3-4周
M-4  美术资产迁移（立绘厚涂+精灵Q版/角色/怪物/建筑） ⛰️ downhill  ~4-8周（黑机）
M-5  世界观叙事接入（CG演出层 + 环境叙事）        ⛰️ downhill  ~2周
M-6  正式上线（v3.0.0）                          ⛰️ downhill  ~1周
```

**总估算**：7-13 周（取决于黑机美术产能和 PoC 验证结果）

### 2.2 依赖关系图

```
M-1 等距PoC ──┬──成功──> M-3 引擎重构+氛围层 ──> M-5 叙事接入 ──> M-6 上线
              │                                  ↑
              └──失败──> 回退横版 + ADR-005 CG演出层 + 独立氛围层
                                              ↑
M-2 ADR-006+美术PoC ──成功──> M-4 美术迁移 ──┘
                  └──失败──> 降级：保持现有像素精灵，仅做视角+氛围，立绘/漫画可独立推进
```

**关键决策门**：M-1 和 M-2 是 PoC 验证节点，失败则回退，不硬推。

### 2.3 各里程碑详情

---

### M-1：等距俯视角 PoC（最小验证）⚠️ 决策门

| 维度 | 内容 |
|---|---|
| 状态 | ⛰️ uphill（需验证可行性，可能失败） |
| 目标 | 用最小成本验证"Phaser 4 能否稳定支持等距视角"，不追求完整 |
| 依赖 | 无 |
| 工作量 | ~1 周 |
| 退出条件 | ① 一个等距房间能渲染 ② 一个角色能用8方向移动 ③ 碰撞判定正确 ④ 深度排序无闪烁 ⑤ 多人同步不炸 |
| 假设 | A1: Phaser 4 无官方 isometric 支持，但社区插件或自写投影转换可行 |
| 决策门 | **PoC 失败则回退**，继续用横版 + 独立氛围层 + ADR-005 CG演出层 |

**子任务**：
1. 技术选型调研：`phaser3-isometric-plugin` vs 自写等距投影转换 vs Tiled 等距导出
2. 坐标系统实现：世界坐标 ↔ 屏幕坐标转换函数
3. 最小场景：一个等距房间（地板+墙壁），用色块占位
4. 角色移动：8方向移动 + 等距碰撞体
5. 深度排序：按 `(x+y)` 动态排序，验证多人同框无闪烁
6. Colyseus 同步验证：等距坐标能否走通现有 onStateChange diff

---

### M-2：ADR-006 方向锁定 + 美术风格 PoC ⚠️ 决策门

| 维度 | 内容 |
|---|---|
| 状态 | ⛰️ uphill（需验证美术可行性） |
| 目标 | ① 正式发 ADR-006 锁定等距方向 ② 验证 AI 能否批量生成分层美术资产（立绘/漫画=美漫厚涂，精灵=Q版/低分辨率） |
| 依赖 | M-1 PoC 通过（否则不启动） |
| 工作量 | ~1 周 |
| 退出条件 | ① ADR-006 Accepted ② ComfyUI 能生成1套美漫厚涂风角色立绘 ③ 精灵方向确认（Q版或低分辨率降采样） ④ 风格与设定集调性一致 |
| 假设 | A2: ComfyUI + 适当 LoRA/model 能产出美漫厚涂风（Hades/Jen Zee 路线），画风一致性靠专属 LoRA |
| 决策门 | **美术 PoC 失败则降级**：保持现有像素风，只做视角+氛围重构，立绘/漫画可独立推进 |

**子任务**：
1. ADR-006 编写：锁定等距俯视角方向 + 分层美术方案，记录决策依据/替代方案/影响评估
2. 美术风格调研：美漫厚涂风拆解（Hades/Jen Zee 式角色张力、环境插画、暗色高饱和），参考 WLOP 鬼刀厚涂方向
3. ComfyUI 工作流 PoC：用男德通角色做1套美漫厚涂风立绘（验证 LoRA 可行性）
4. 精灵画风决策：Q版精灵 vs 低分辨率厚涂降采样，对比等距视角下的辨识度和开发成本

---

### M-3：等距引擎重构 + 环境氛围层

| 维度 | 内容 |
|---|---|
| 状态 | ⛰️ downhill（PoC 通过后方案已定） |
| 目标 | 全量重写前端游戏层为等距视角，同时内置环境氛围层（昼夜/天气/光影/音效） |
| 依赖 | M-1 通过 + M-2 ADR-006 Accepted |
| 工作量 | ~3-4 周 |
| 退出条件 | ① 塔楼3层等距渲染 ② 森林战斗区等距渲染 ③ 怪物追击+攻击正常 ④ 多人同框无闪烁 ⑤ 爬梯/门交互正常 ⑥ 昼夜交替可见 ⑦ 至少1种天气效果 ⑧ 区域氛围区分（塔楼暖光/森林暗绿光） ⑨ 环境音效播放 |
| 假设 | A3: 现有 Colyseus Schema 不需改动，仅客户端渲染层重写 |

**子任务**：
1. 地图系统重写：Tiled 等距地图导出 + Phaser 加载 + 碰撞体生成
2. 塔楼3层等距重建：底层大厅/中层房间/高层哨位，菱形铺设
3. 森林战斗区等距重建：树木/灌木/边界，等距摆放
4. 角色系统重写：8方向精灵 + 等距移动 + 深度排序
5. 怪物系统适配：等距追击 AI + 碰撞 + 深度排序
6. 交互系统适配：NPC/物品/门/传送门等距交互判定
7. HUD 适配：等距坐标下的交互提示气泡位置
8. 昼夜系统：背景色渐变 + 等距光照遮罩
9. 天气系统：粒子系统（雨/雪/雾），影响画面能见度
10. 区域氛围：shader 或 tint 区分安全区（塔楼暖黄光）/危险区（森林暗绿光）
11. 环境音效：白天鸟鸣/夜晚虫鸣/战斗紧张BGM，音频调度器
