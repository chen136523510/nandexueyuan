## 0. 背景与决策依据

### 0.1 院长决策（2026-07-27）

- **方向**：德塔从"横版像素风"重构为"饥荒式展示形态"（等距俯视角 + 环境氛围叙事 + 手绘暗黑童话美术风）
- **三个维度都要**：① 等距俯视信息密度 ② 环境氛围叙事（昼夜/天气/光影）③ 饥荒美术质感
- **资产态度**：现有横版像素资产（R-003 精灵表等）可接受推倒，"船小好掉头"
- **前提**：先做战略规划（里程碑），不立即开发
- **深层诉求**：需要项目管理机制，保证 AI 新窗口能轻松接手进度

### 0.2 与 ADR-005 的关系

ADR-005 决策3末尾明确保留："若未来确有'更沉浸的探索'需求，优先在 2D 内升级（如 2D 俯视角），而非切 3D"。本规划即走这条预留路径，**不违背 ADR-005**，但需新增 ADR-006 正式锁定此方向。

### 0.3 资产损失评估

| 资产 | 复用性 | 处置 |
|---|---|---|

| 世界观设定集（118年/六大势力） | ✅ 完全复用 | 不动 |
| 立绘/头像 PNG | ✅ 完全复用 | 不动 |

## 1. AI 协作项目管理机制升级

### 1.1 现状诊断

本仓库已有成熟的战术级协作机制（handoff/sync-docs/ADR/release-helper），但缺少**战略级**管理：

| 层级 | 现有机制 | 缺口 |
|---|---|---|
| 战术级（单次任务） | `.ai/handoff.md` 交接单 + sync-docs 技能 | ✅ 成熟 |
| 里程碑级（版本发布） | ADR-004 版本号 + release-helper 技能 | ✅ 成熟 |
| **战略级（跨里程碑路线图）** | 无 | **❌ 缺口** |

缺口导致的 AI 接手问题：
- 新会话只看到"上次做到哪"，看不到"整体往哪走"
- AI 无法判断当前任务在整个路线图中的位置和优先级
- 探索性任务（uphill）和确定性任务（downhill）混在一起，AI 容易在未验证的假设上铺代码

### 1.2 升级方案：三层协作体系

```
战略层（本文件）     → prd/01-需求文档/00-基础数据/ROADMAP.md    ← 跨里程碑路线图
里程碑层（现有）     → ADR-004 + release-helper + CHANGELOG       ← 版本快照
战术层（现有）       → .ai/handoff.md + sync-docs + AGENTS.md     ← 每次会话交接
```

### 1.3 新增文件：`ROADMAP.md`（战略级路线图）

放在 `prd/01-需求文档/00-基础数据/ROADMAP.md`，作为 AI 新会话接手时的**第二份必读文件**（第一份是 handoff.md）。

**结构规范**：
```markdown
# 男德学院产品路线图

## 当前里程碑：M-XXX（名称）
- 状态：uphill（探索中）/ downhill（执行中）/ completed
- 假设表：列出 2-3 个关键假设及验证状态
- 退出条件：客观可验证的标准

## 里程碑列表（倒序）
### M-XXX（最新）
### M-XXX-1（上一个）
...

## 假设登记簿
| 编号 | 假设 | 验证方法 | 状态 |
```

### 1.4 山丘图（Hill Chart）标注机制

借鉴 Shape Up 方法，每个任务标注 uphill/downhill：

| 标注 | 含义 | AI 行为 |
|---|---|---|
| ⛰️ uphill | 问题还没想清楚，方案未定 | **禁止直接写代码**，先做 PoC/调研/方案验证 |
| ⛰️ downhill | 方案已定，可预估工作量 | 可直接执行，按步骤清单推进 |

在 handoff.md 的"待办"部分，每项任务标注 uphill/downhill。

### 1.5 会话接手协议（升级版）

AI 新会话开场必读顺序：
1. `AGENTS.md`（项目纪律 + 技术栈 + 踩坑）— 已有
2. `.ai/handoff.md`（上次做到哪 + 进行中任务 + 环境状态）— 已有
3. `prd/01-需求文档/00-基础数据/ROADMAP.md`（整体往哪走 + 当前里程碑）— **新增**

会话结束必做：
1. 更新 `.ai/handoff.md`（进行中任务 + 进度百分比）— 已有
2. 执行 sync-docs 技能同步四文档 — 已有
3. 若里程碑状态变化，更新 `ROADMAP.md` — **新增**

## 2. 饥荒形态重构里程碑路线图

### 2.1 里程碑总览

```
M-1  环境氛围层（横版上叠加，纯增益）           ⛰️ downhill  ~1.5周
M-2  等距俯视角 PoC（最小验证）                  ⛰️ uphill    ~1周
M-3  ADR-006 方向锁定 + 美术风格 PoC             ⛰️ uphill    ~1周
M-4  等距引擎重构（坐标/碰撞/深度排序）           ⛰️ downhill  ~2-3周
M-5  手绘美术资产迁移（角色/怪物/建筑）           ⛰️ downhill  ~4-8周（黑机）
M-6  世界观叙事接入（CG演出层 + 环境叙事）        ⛰️ downhill  ~2周
M-7  正式上线（v3.0.0）                          ⛰️ downhill  ~1周
```

**总估算**：8-14 周（取决于黑机美术产能和 PoC 验证结果）

### 2.2 依赖关系图

```
M-1 环境氛围层 ──────────────────────────┐（可独立先做，纯增益）
                                          │
M-2 等距PoC ──┬──成功──> M-4 引擎重构 ──> M-6 叙事接入 ──> M-7 上线
              │                              ↑
              └──失败──> 回退横版，M-1氛围层 + ADR-005 CG层继续
                                              ↑
M-3 ADR-006+美术PoC ──成功──> M-5 美术迁移 ──┘
                  └──失败──> 美术改回像素风，仅做视角+氛围
```

**关键决策门**：M-2 和 M-3 是 PoC 验证节点，失败则回退，不硬推。

### 2.3 各里程碑详情

---

### M-1：环境氛围层（横版叠加，纯增益）

| 维度 | 内容 |
|---|---|
| 状态 | ⛰️ downhill（方案明确，技术成熟） |
| 目标 | 在现有横版上叠加昼夜/天气/光影/音效，提升世界观氛围感 |
| 依赖 | 无（独立于等距重构） |
| 工作量 | ~1.5 周 |
| 退出条件 | ① 昼夜交替可见（背景渐变+光照遮罩）② 至少1种天气效果（雨/雪）③ 塔楼区域=暖光、森林区域=暗绿光 ④ 环境音效播放 |
| 假设 | A1: Phaser 4 的 Graphics/lighting 足够实现昼夜效果 |
| 价值 | 即使最终不转等距，这层也是纯增益 |

**子任务**：
1. 昼夜系统：背景色渐变 + 全局光照遮罩（Phaser spotlight/mask）
2. 天气系统：粒子系统（雨/雪/雾），影响画面能见度
3. 区域氛围：shader 或 tint 区分安全区（塔楼暖黄光）/危险区（森林暗绿光）
4. 环境音效：白天鸟鸣/夜晚虫鸣/战斗紧张BGM，音频调度器

---

### M-2：等距俯视角 PoC（最小验证）

| 维度 | 内容 |
|---|---|
| 状态 | ⛰️ uphill（需验证可行性，可能失败） |
| 目标 | 用最小成本验证"Phaser 4 能否稳定支持等距视角"，不追求完整 |
| 依赖 | 无 |
| 工作量 | ~1 周 |
| 退出条件 | ① 一个等距房间能渲染 ② 一个角色能用8方向移动 ③ 碰撞判定正确 ④ 深度排序无闪烁 ⑤ 多人同步不炸 |
| 假设 | A2: Phaser 4 无官方 isometric 支持，但社区插件或自写投影转换可行 |
| 决策门 | **PoC 失败则回退**，继续用横版 + M-1氛围层 + ADR-005 CG演出层 |

**子任务**：
1. 技术选型调研：`phaser3-isometric-plugin` vs 自写等距投影转换 vs Tiled 等距导出
2. 坐标系统实现：世界坐标 ↔ 屏幕坐标转换函数
3. 最小场景：一个等距房间（地板+墙壁），用色块占位
4. 角色移动：8方向移动 + 等距碰撞体
5. 深度排序：按 `(x+y)` 动态排序，验证多人同框无闪烁
6. Colyseus 同步验证：等距坐标能否走通现有 onStateChange diff

### M-3：ADR-006 方向锁定 + 美术风格 PoC

**子任务**：
