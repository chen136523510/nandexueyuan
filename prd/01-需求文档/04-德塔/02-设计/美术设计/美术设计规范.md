## 1. 视觉风格

### 1.1 总体定位

| 维度 | 设定 |
|------|------|
| 形态 | 视觉小说（叙事驱动 + 立绘 + 背景 + 对话 + 分支） |
| 画风 | 西方奇幻油画厚涂（见 §1.2 画风描述） |
| 色调 | 黑深残世界基调，角色立绘温暖有质感 |
| 情感 | 外部世界黑暗残酷，学院成员戏谑反差 |

### 1.2 画风描述（出图/视频语义提示词基准）

> 当前出图工具为豆包 Seedream API / MiniMax 等语义模型，用**完整中文语义描述**引导画风，不再堆叠英文关键词。以下描述可直接用于 prompt 或作为参考图搭配的画风说明。

**核心画风**：

西方奇幻油画厚涂风格。笔触厚重饱满，可见油画颜料的堆叠感和湿润感，不是平涂赛璐璐，不是水彩透明感，不是数码插画的干净平整。色彩过渡柔和，暗部有层次不死黑，亮部有光泽不刺眼。光影戏剧性强，明暗对比鲜明，人物和场景都有强烈的体积感和重量感。

**色调氛围**：

整体偏暗色基调，世界残酷沉重，但人物身上打暖光，有温度有质感，不灰暗不阴冷。史诗感，庄严感，不是轻松日常风。

**人物特征**：

写实比例，五官偏西方奇幻的深邃轮廓。不萌系、不大眼Q版、不日漫二次元。

**明确排除的画风**：日漫动漫风、赛璐璐平涂、Q版/萌系、水彩、素描线稿、3D渲染、照片写实。

**出图/出视频时**：传现有立绘或背景图作为参考图，让模型继承画风。不需要在 prompt 里反复描述画风，参考图本身即画风基准。代表性参考资产：
- 人物：`public/visualnovel/portraits/qiu/rogue.webp`（丘游侠）、`president.webp`（丘总统）
- 场景：`public/visualnovel/bg/bridge_wide.webp`（帝桥远景）、`negotiation_standoff.webp`（谈判全景）

### 1.3 画风统一原则

- 所有角色和场景共用同一画风，保持视觉统一
- 通过服装/配饰/色彩/气质区分个体，不换画风
- 出图前传 1-2 张已有资产作参考图锁画风，比纯文字描述更可靠

## 3. 色彩规范

### 3.1 角色配色原则

- 每个角色有辨识度配色，不撞色不撞衫
- 配色逻辑服务于角色设定（如汪神蓝=水，法刺幸深蓝=帝国庄重）

## 4. 立绘规范

### 4.1 立绘尺寸与格式

| 资源类型 | 尺寸 | 格式 | 说明 |
|----------|------|------|------|
| 角色立绘 | 832×1216 | PNG 透明背景 | 抠图后入库 |
| 背景图 | 1920×1080 | JPG | 场景背景 |
| CG 图 | 1920×1080 | JPG | 特殊剧情演出 |
| 物品图标 | 128×128 | PNG 透明背景 | 储物空间 UI |

### 4.2 立绘资源路径

```
public/visualnovel/
├── portraits/     ← 角色立绘（抠图后透明背景）
├── bg/           ← 背景图
├── cg/           ← CG 演出图
└── items/        ← 物品图标
```

### 4.3 立绘命名规范

```
portrait_{角色名}_{表情/姿态}.png

示例：
portrait_rui_serious.png        ← 睿帝 严肃
portrait_xing_smile.png         ← 法刺幸 微笑
portrait_tian_laugh.png         ← 添 大笑
bg_tower_interior.png           ← 塔楼内部背景
item_rui_emblem.png             ← 睿帝令 物品图标
```

> 注：实际入库路径为 `public/visualnovel/portraits/{角色id}/{表情}.png`（如 `dean/normal.png`），
> prologue.js 中 portrait 字段格式为 `"{角色id}/{表情}"`。

### 4.4 立绘交互规则（三态系统 + 舞台状态）

立绘显示状态由 **speaker（说话人）驱动**，引擎运行时自动推导，不依赖数据手写 active 字段。

| 状态 | 触发条件 | 视觉表现 |
|------|----------|----------|
| **active**（说话人） | 当前节点 speaker 为该角色 | 立绘**上移 24px** + **提亮**（brightness 1.12, saturate 1.08） |
| **narrator**（旁白态） | 当前节点 speaker='旁白'，所有在场角色 | 全部**对齐 baseline**（不上移），正常亮度（brightness 1.0） |
| **dim**（非说话人） | 有人说话但不是该角色 | **变暗**（brightness 0.55, saturate 0.4），不上移 |

**切换规则**：
- 旁白时，所有在场立绘高度一致（对齐）
- 有人说话时，说话人立绘向上移动并提亮
- 另一人接话或进入旁白时，原说话人立绘回归正常，新说话人上移提亮
- 过渡动画 0.4s ease

#### 4.4.1 舞台状态机制（角色持续在场）

> **核心原则：角色一旦登场，持续在场（dim/narrator），直到显式退场。**
> 解决「多人对话时一个出现一个消失」问题（2026-07-31 引入）。

剧本节点通过三种字段控制舞台（当前在场角色集合，跨节点持久化）：

| 字段 | 作用 | 使用场景 |
|------|------|----------|
| `characters: [{id, portrait, position}]` | **绝对声明**（重置舞台为该集合） | 场景首次出场、换场景重声明；空数组 `[]` 显式清场 |
| `enter: [{id, portrait, position}]` | **增量登场**（合并入舞台） | 角色首次上场、已在场角色切换表情/位置 |
| `exit: ['xing']` | **增量退场**（从舞台移除） | 角色真正离开场景，触发退场动画 |
| 三者都没有 | **延续不变** | 多人对话切说话人时用（核心：避免来回消失） |

处理优先级：`exit` 先于 `enter`（避免同帧进出不同角色时闪烁）。

**技术实现**：
- `types.js`：`SPEAKER_TO_ID` 映射表 + 舞台字段 JSDoc
- `visualNovelStore.js`：`stage` ref 维护在场角色，`applyStageChange()` 在 goToNode 时更新；`currentCharacters` computed 基于 stage + speaker 推导 state
- `CharacterLayer.vue`：三态 CSS class + 真实立绘 `<img>` 渲染（TransitionGroup 入退场动画）
- 存档快照包含 stage 字段，读档时恢复

## 7. 设计原则总结

1. **画风统一**：所有角色和场景共用同一画风，传已有资产作参考图锁画风，不换画风
2. **脸模先行**：AI 出图确定脸模/气质/配色，正式资产需按剧情专门出图+抠图
3. **辨识度优先**：剪影 > 配色 > 材质，远看认得出角色
4. **发色必查**：出图前查发色速查表，防止发色错误
5. **年龄精确**：SDXL 对年龄词敏感，需精确选择描述词
