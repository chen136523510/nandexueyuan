# 内政-战场联动（红警范式）

> 状态：✅ 框架已定 · 二期核心卖点
> 设计原则：**同一套设施数据，一期折算结算数值，二期直接变成战场实体。**

## 映射表

| 内政建造 | 一期（数值结算）效果 | 二期（实时战场）实体形态 |
|---|---|---|
| 城墙（等级） | 城防值上限、攻城减伤/坚守 | 环绕市中心核心区的可破坏墙体 + 城门（突破点） |
| 军事基地 | 守军兵力上限、训练度加成 | 战场内"出兵建筑"：战损补充/援军刷出点；被拆=失去补兵能力 |
| 城防箭塔（基地附属） | 守方杀伤系数 | 自动射击的防御塔（红警哨戒炮逻辑） |
| 农田/商业中心 | 城内存粮/金（影响围城坚持时间） | 城外地表建筑，可被攻方掠夺（焦土压力，逼野战） |
| 娱乐中心 | 守军士气/民生 | 市中心附近士气光环 |
| 科技线节点 | 解锁兵种/结算系数 | 新兵种单位、建筑外观与攻击方式升级 |
| 城市范围（发育度） | 破城难度系数 | 战场半径/塔位数/市中心离城门距离（见 [01-地图与城市/城市成长与城防.md](../01-地图与城市/城市成长与城防.md)） |

## 胜负目标

攻方：突破城墙防线 → **占领市中心** = 完全占城（R11 定；军事基地为必经削弱目标）。守方：拖到攻方粮草耗尽，或占领攻方根据地。详见 [战斗总述.md](./战斗总述.md) 胜负节。

## 架构纪律

一期引擎数据结构必须从第一天就把"设施等级/位置"建成战场可读模型，严禁内政数据与战场数据各写一套——这是"一期不返工"的关键约束（见 [07-技术架构/架构总述.md](../07-技术架构/架构总述.md)）。
