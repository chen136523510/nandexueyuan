# 存档设计

> 状态：🏗️ 草案 · 一期落地

## 方案

- **主存档**：浏览器 LocalStorage（小存档）或 IndexedDB（容量大，推荐）；
- **导出/导入**：JSON 文件下载/上传（换机器、分享存档、调试）；
- 存档内容=引擎完整状态快照（城市/武将/资源/外交/时间/事件状态），因引擎与 UI 分离且状态只经指令总线变更，快照可直接序列化。

## 存档位（待 UI 设计）

- 自动存档（每 N 月/退出时）+ 若干手动档位；
- 修改器改动写入同一状态（不另立作弊档，但可打标记）。

## 数据文件（非存档，静态配置）

JSON 数据驱动，与引擎逻辑分离：

| 文件（拟） | 内容 |
|---|---|
| cities.json | 13 城：阵营/城型/邻接/地标特色/初始建设 |
| officers.json | 21 将：阵营/驻守/四维/特技/技能/初始忠诚 |
| tactics.json | 技能/战法模板（伤害/增益/弱化/恢复） |
| techs.json | 科技树（专题后） |
| events.json | 起义/天灾/异族事件定义 |
| balance.json | 所有可调数值（便于一期成型后统一微调，修改器也可改运行时值） |

## 版本兼容

存档带 schema 版本号；数值/结构迭代时做迁移函数（开发期可直接清档，上线后需兼容）。
