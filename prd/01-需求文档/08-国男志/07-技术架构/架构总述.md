# 架构总述

> 状态：✅ 已定（R1/R4）

## 技术选型

| 项 | 定案 |
|---|---|
| 形态 | Web 单机（Vue 3 + TS + Canvas/PixiJS 候选） |
| 引擎 | 纯 TS 游戏引擎，与 UI 分离，可单测 |
| 数据 | JSON 数据驱动：`cities.json`/`officers.json`/`tactics.json` 等；存档即 JSON |
| 运算 | **浏览器权威**：大地图 tick、内政产出、战斗模拟、算法 AI 全部本地运行 |
| 依赖 | 全自研/开源/免费，零订阅 |

## 分层

```
Vue UI（大地图/城市面板/战场渲染/设置）
        ↑ 只读状态 + 下发 command
纯 TS 引擎（唯一状态源：城市/武将/资源/外交/战斗）
  ├── 规则系统（内政产出/忠诚起义/俘虏处置/外交判定）
  ├── 算法 AI（三阵营内政军事：边际收益分配+威胁图+机会评分）
  └── 战斗模型（自动/手动两档共用的同一套判定）
```

- LLM 永远不直接改状态：二期军师只读 snapshot、外交 LLM 只出提案，均经 JSON Schema + 规则闸门（见 [05-外交/关系规则与LLM.md](../05-外交/关系规则与LLM.md)）。
- 算法 AI 不抄三国志 12 的"2 倍兵力橡皮筋"和低效自动分配；难度做成显式参数（资源系数/侵略性/反应延迟），决策可解释（记录"因为城市 X 市场边际收益更高"）。

## 第一天就必须遵守的数据约束

1. 所有状态变更走**指令总线**（见 [指令总线与修改器.md](./指令总线与修改器.md)）；
2. 设施数据（等级/位置）从第一版就建成**战场可读模型**，二期直接渲染实体，不写两套数据（见 [04-军事/内政战场联动.md](../04-军事/内政战场联动.md)）；
3. 战斗判定模型一期即按"自动档=手动档共用"设计；
4. JSON 数据与引擎逻辑分离，便于修改器与平衡性调整。

## 不做

- 不做网络对战/多人同步；
- 不做服务端对局模拟；
- 首版不做 3D（需要时再评估 Unity 迁移，引擎层保持与渲染解耦以留余地）。
