# 美术工作纪律（红线，强制）

> 本文件由 AGENTS.md 外迁（2026-10-04 院长裁决：AGENTS 瘦身，美术纪律只在处理美术工作时读取）。
> **处理立绘出图 / 美术资产入库 / 美术图片移动清理之前，必须先读本文件。** 原文完整保留，效力不变。

## 一、立绘制作纪律（红线，强制）

> 本节是角色立绘出图的全局规范，**任何美术会话都必须遵守，不得因上下文截断而遗忘**。

1. **服饰一致性优先**：在没有明确剧情安排或用户明确指示的情况下，**同一角色的服饰、装扮、外表必须保持一致**。不能因为"重新出图"或"换表情"就改变服装、发色、配饰。服装变更须有剧情理由且经用户确认。

2. **表情差分原则（定版驱动）**：角色立绘先出**一张定版基准图**（base）。表情/动作差分（smile/cold/serious 等）基于这张定版图，通过 Seedream API（脸模+服装双参考）生成，**保证同一套服饰下的表情变化**，不能各出各的导致服装不统一。

3. **服饰须经用户过目**：角色的服饰装扮在正式批量出图前，**必须先出一张给用户过目确认**。用户确认后该服饰即锁定为该角色定版，后续表情差分均基于此。未确认不得批量出图。

4. **带背景原图必须留存**：AI 出图后，**带背景的原图必须保存**到 `.ai/seedream-test/` 或对应角色目录（已在 .gitignore）。抠图后的透明 PNG 入库 `public/`。**严禁只保存抠后结果**——否则后续换抠图方案时无法重抠。

5. **规划先于出图**：删除或重做立绘后，必须先输出「立绘规划清单」（谁出场、需要几套、每套服饰依据、表情需求），经用户确认后再出图。

6. **立绘展示位置统一**：所有立绘在游戏内展示时，**小腿中部位置对齐屏幕最下方水平线**。即立绘整体下移，脚部和小腿下半部分超出屏幕底部（不可见），上半身更突出。CSS 通过 `.char-portrait { bottom: 负值 }` 实现，具体偏移量需根据实际立绘比例调试确定。

7. **幸的立绘基准源自背景图**：幸的定版立绘以背景图 `tower_outdoor_mist` 中幸的形象为基准（锁服装/气质/姿态），先从背景图提取形象生成定版图，再做表情差分。院长和添的立绘按各自形象设计文档出图。

## 二、美术资产 README 纪律（红线，强制）

> **任何美术图片入库 `public/` 时，必须同步在美术资产 README 中登记并写明该图的内容。** AI 视觉模型对图片内容的描述不可靠（AGENTS 已多次记录视觉模型"描述雷同/模板化缓存/不可全信"），因此入库资产的内容必须由人工/AI 在出图时**以文字记录**，而非事后让模型看图反推。

1. **入库即登记**：每张图片（立绘/背景图/道具图/CG/表情差分）入 `public/` 的同一次提交，必须同步更新对应的 README。**入库图片但未补 README = 任务未完成**（等同代码改了文档没更新）。
2. **登记位置**：统一登记到 `prd/01-需求文档/04-德塔/02-设计/形象设计/美术资产/README.md`（现有清单表）。按资产类型分表：
   - 背景图 →「背景图」表（文件名 + 场景内容：地点/光线/人物入画情况/用途章节）
   - 立绘/表情差分 →「角色立绘 + 表情差分」表（角色 + 基准/差分 + 情绪 + 运行时目录）
   - 道具图 → 新增「道具图」表（文件名 + 道具内容：材质/纹样/魔法元素/触发节点）
   - CG → 归入背景图表并标注「CG-N」
3. **描述须写实际内容，不是文件名翻译**：必须写明图里画了什么——场景包含哪些人物、人物姿态/朝向、关键道具/标志、光线氛围、构图焦点。例如「谈判全景·对峙：四角色入画，幸左↔见右四目相对，添坐见右手一个身位，班楼梯口靠墙闭目，桌上羊皮卷隐隐发光」，而不是笼统的「谈判场景」。
4. **出图方负责写**：谁出图谁登记。黑机出图时同步补；白机若在代码层接入新资产，发现 README 缺该项，必须补登记后再算完成。
